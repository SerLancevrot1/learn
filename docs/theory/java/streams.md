# Stream API: предсказываем выполнение и выбираем коллектор

[Java](README.md) · [Лямбды и Optional](language.md#11-лямбды-stream-api-optional) · [Упражнения в проекте](../../../src/main/java/ru/learn/stream/api/EXERCISES.md)

**Ответ за минуту.** Stream описывает проход по данным как источник, промежуточные операции и терминальное действие. `map` преобразует элемент, `flatMap` разворачивает вложенные элементы, `reduce` сводит значения, `collect` накапливает результат. Терминальная операция запускает обход, а короткозамыкающие операции могут закончить его раньше.

## Сколько элементов реально обработается

```java
var first = List.of("ant", "owl", "bear", "cat").stream()
    .filter(word -> word.length() == 3)
    .map(String::toUpperCase)
    .findFirst();
```

Для последовательного потока `findFirst` ищет первый элемент в порядке источника. Уже `ant` проходит фильтр, превращается в `ANT` при обычной локали и завершает поиск. Конвейер обрабатывает элемент через цепочку операций, потом при необходимости берёт следующий. Отдельный список после `filter` здесь не создаётся. В прикладном коде для стабильной нормализации текста используй `word.toUpperCase(Locale.ROOT)`.

| Оператор | Что меняется | Что помнить |
| --- | --- | --- |
| `map` | На каждый вход один выход | `map(Order::lines)` даёт поток списков |
| `flatMap` | На один вход от нуля до многих выходов | `flatMap(order -> order.lines().stream())` даёт поток позиций |
| `filter` | Проходят элементы, принятые предикатом | Фильтр до дорогого преобразования экономит работу, если сохраняет смысл |
| `distinct` | Остаётся по одному представителю по `equals` | Нужно помнить уже встреченные элементы |
| `sorted` | Меняется порядок | На обычном неотсортированном источнике надо получить вход целиком до выдачи первого элемента |
| `limit(n)` | Ограничивает число выходов | `limit(10).sorted()` сортирует первые десять, а `sorted().limit(10)` ищет десять меньших |

Например, `Stream.iterate(0, n -> n + 1).limit(5).sorted().toList()` закончится с пятью числами. Если поставить `sorted` перед `limit`, сортировка не получит конец бесконечного источника. Для выбора пяти минимумов из большого конечного набора можно использовать кучу размера пять за `O(n log 5)` и затем отсортировать её. [Кучи и задачи Top-K](../algorithms/algorithms.md)

### Побочные эффекты и повторное использование

Stream рассчитан на проход один раз. После терминальной операции для следующего прохода создай новый поток из коллекции или с помощью поставщика. Изменение источника прямо в конвейере нарушает требования для обычных коллекций. При необходимости сначала построить список изменений, затем применить их отдельным шагом.

```java
long count = List.of(10, 20, 30).stream()
    .peek(System.out::println)
    .count();
```

API разрешает вычислить `count()` из известного размера источника, потому что `peek` размер не меняет. В таком случае печати не будет. Поэтому не помещай в `peek` запись аудита или изменение обязательного состояния. Когда нужен именно каждый вызов, используй терминальное действие или обычный цикл, где порядок и эффекты видно напрямую.

## Выбираем итоговую форму данных

| Результат | Операция | Уточнение |
| --- | --- | --- |
| Список в порядке обхода | `toList()` (Java 16+) | Возвращает неизменяемый список. Для конкретной изменяемой реализации используй `toCollection(ArrayList::new)` |
| Ключ → список строк | `groupingBy(key)` | Удобно сохранять все элементы группы |
| Ключ → агрегат | `groupingBy(key, downstream)` | Можно сразу получить сумму, число или максимум каждой группы |
| Уникальный ключ → значение | `toMap(key, value, merge)` | При повторе ключа заранее определи политику слияния |
| Две группы по условию | `partitioningBy(predicate)` | Коллектор предоставляет результаты для `true` и `false` |

**Предметный пример.** API выставляет счета. В бухгалтерской выгрузке нужны число позиций и сумма по каждому клиенту. Суммы хранятся в копейках. Отдельно нужен справочник «ID позиции → последняя версия».

```java
record Line(long id, String customer, long cents, long version) {}

var lines = List.of(
    new Line(1, "A", 200, 1),
    new Line(2, "A", 300, 1),
    new Line(3, "B", 700, 1)
);

Map<String, Long> totals = lines.stream().collect(
    Collectors.groupingBy(Line::customer, Collectors.summingLong(Line::cents))
);

Map<Long, Line> latest = lines.stream().collect(Collectors.toMap(
    Line::id,
    Function.identity(),
    BinaryOperator.maxBy(Comparator.comparingLong(Line::version))
));
```

В `totals` получатся значения `A → 500` и `B → 700`. При двух версиях одного ID второй коллектор выберет запись с большей версией. Для равенства версий определись, считаются ли записи одной и той же или конфликтующими. Если повторный ID нарушает требование, оставь вариант `toMap` без функции merge: он явно сигнализирует о дубле исключением. При необходимости воспроизводимого порядка обхода передай фабрику `LinkedHashMap::new` в четырёхаргументный `toMap` и определи порядок источника.

`Stream.toList()` и `Collectors.toList()` имеют разные контракты. Второй не гарантирует тип, изменяемость и потокобезопасность результата. `Collectors.toUnmodifiableList()` гарантирует неизменяемость и отклоняет `null`. Неизменяемый список сохраняет ссылки на элементы. Если элемент изменяем, его состояние можно поменять через другую ссылку.

## Reduce, collect и parallel stream

`reduce` применяет операцию над значениями. Для суммирования `Long::sum` нейтральный элемент равен 0. Для параллельного исполнения важно, чтобы разные способы сгруппировать элементы давали один итог. Вычитание не ассоциативно: `(10 - 3) - 2 = 5`, а `10 - (3 - 2) = 9`. Конвейер с вычитанием через `reduce` не задаёт переносимое параллельное вычисление.

`collect` подходит, если результат накапливается в изменяемом контейнере. **Supplier** создаёт пустой контейнер, **accumulator** добавляет элемент, **combiner** сливает частичные результаты, **finisher** при необходимости преобразует контейнер. В обычном параллельном collect отдельные части могут получить разные контейнеры, которые в конце объединяют. Поэтому стандартный коллектор списка может пользоваться `ArrayList` без общей блокировки на каждом добавлении.

```java
var numbers = List.of(1, 2, 3, 4);
var doubled = numbers.parallelStream()
    .map(n -> n * 2)
    .collect(Collectors.toCollection(ArrayList::new));
```

Результат `[2, 4, 6, 8]` сохраняет порядок исходного списка. Замена коллектора на `parallelStream().forEach(sharedList::add)` добавляет гонку при использовании обычного `ArrayList`. `forEach` в параллельном потоке не гарантирует порядок вывода, `forEachOrdered` сохраняет порядок источника, когда он задан. Упорядочивание может увеличить цену объединения или ограничить параллелизм.

### Когда параллельность помогает

Для CPU-работы над большим массивом источник легко делится на части, вычисления независимы, а слияние дёшево. Это кандидат для измерения parallel stream. Для маленького списка, коротких действий или тяжёлого слияния карт накладные расходы могут перекрыть выигрыш. Измеряй на репрезентативных размерах с прогревом. У `double` из-за округления чисел результат отдельных способов группировки сложения может слегка отличаться.

HTTP-запросы из `parallelStream` занимают общие worker-потоки реализаций JDK и затрудняют контроль дедлайна и нагрузки по зависимостям. Для параллельных вызовов нужны ограничитель обращений, тайм-ауты клиента и политика частичного результата. Механизмы для этого смотри в [конспекте по выполнению задач](async.md).

## Самопроверка

<details>
<summary>Как получить три самых дешёвых товара из списка с ценами [8, 1, 10, 2, 3]?</summary>

`sorted().limit(3)` даст `[1, 2, 3]`. `limit(3).sorted()` сортирует только первые три и даст `[1, 8, 10]`. Для огромного входа обсуди ограниченную кучу и порядок равных цен.

</details>

<details>
<summary>Почему на новом входе toMap начал падать, хотя внешний ID никогда не null?</summary>

Два объекта могли получить одинаковый ключ. Проверь, что ключ действительно уникален, или укажи политику разрешения дублей. Например, для разных версий одной записи выбирай по версии. Для нарушения бизнес-уникальности полезно оставить ошибку.

</details>

<details>
<summary>Почему reduce с общей изменяемой коллекцией как identity ломается при parallel?</summary>

Разные части используют нейтральный элемент как начальное значение. Если он общий и мутируется, части могут менять один объект и повторно включать его содержимое при слиянии. Для сбора используй collect с отдельным контейнером на часть.

</details>

<details>
<summary>Как сгруппировать заказы по клиенту и посчитать только оплаченные?</summary>

Если в результате нужны только клиенты с оплатами, отфильтруй оплаченные заказы перед группировкой и передай `counting()` как downstream. Если нужны также клиенты с нулём, делай группировку всех заказов и применяй `Collectors.filtering(..., counting())` внутри каждой группы.

</details>
