## Повторение перед собеседованием

[Сквозные разборы](interview-cases.md) связывают вопросы о Java, SQL, доставке и выкатке. Выбирай их, когда уже можешь коротко объяснить отдельные механизмы.

Начни с блока, где труднее всего ответить без подсказки. Для Java-бэкенда удобно чередовать темы, чтобы в одной сессии встретились код, механизм и производственный сценарий.

| Если есть 20 минут | Что объяснить вслух |
| --- | --- |
| [Java Core](java/language.md#передача-параметров-и-выбор-метода) и [Stream API](java/streams.md#самопроверка) | Как выбирается перегрузка, сколько элементов обработает поток и где возникнет ошибка с дубликатами |
| [JVM](java/jvm.md#самопроверка) и [асинхронность](java/async.md#самопроверка) | Что отличает ожидание зависимости от работы GC и почему полный пул снижает пропускную способность |
| [JPA](spring/jpa.md#самопроверка) и [PostgreSQL](data/postgresql/diagnostics.md#самопроверка) | Когда виден SQL, где проверяется версия строки и как найти блокирующую транзакцию |
| [HTTP](architecture/communications.md#самопроверка) и [доставка событий](messaging/delivery-patterns.md#самопроверка) | Что произойдёт после тайм-аута платежа или сбоя между commit и ACK |

1. Открой вопрос и дай ответ за минуту из памяти. Для кода сначала запиши ожидаемый результат, для сбоя перечисли, что уже успело сохраниться.
2. Сверь ответ с разбором. Одной строкой запиши, что пропустил, и объясни механизм ещё раз своими словами.
3. Измени одно условие и предскажи результат. Например, поменяй местами `limit` и `sorted` или перенеси падение consumer на момент после commit.
4. Повтори трудное на следующий день, затем примерно через три дня и через неделю. Корректируй интервалы по своим ответам. Если пора переходить к полноценной тренировке, используй [пробные сессии и шкалу оценки](../../INTERVIEW.md#как-работать-с-ответами).

Воспроизведение по памяти и повторение с интервалами помогают удерживать изученное. Дни выше — удобный стартовый график.
