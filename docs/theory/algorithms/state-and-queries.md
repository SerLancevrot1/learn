## Один массив, три режима запросов

Есть массив счётчиков по времени. Если нужна одна сумма, пройди выбранный диапазон. Если массив больше не меняется и сумм много, построй префиксы. Сумма `[l,r)` равна `prefix[r] - prefix[l]`. Если запросы чередуются с изменениями отдельных элементов, одно обновление заставит переписать множество префиксов. Дерево Фенвика хранит суммы блоков так, чтобы менять и читать лишь `O(log n)` блоков.

### Что хранит дерево Фенвика

Внутренние индексы начинаются с 1. Для индекса `i` младший установленный бит `i & -i` равен длине блока, который этим индексом заканчивается. Например, у 12 в двоичном виде 1100 младший бит 4, блок покрывает индексы 9–12. Чтобы собрать префикс 1–12, возьми блок 9–12 и затем префикс 1–8. Прибавление в точке обновляет блоки, которые её содержат: из текущего индекса переходи вверх на длину блока.

```java
final class Fenwick {
    private final long[] tree;

    Fenwick(int size) {
        tree = new long[size + 1];
    }

    void add(int index, long delta) {
        Objects.checkIndex(index, tree.length - 1);
        for (int i = index + 1; i < tree.length; i += i & -i) {
            tree[i] += delta;
        }
    }

    long prefix(int endExclusive) {
        if (endExclusive < 0 || endExclusive >= tree.length) {
            throw new IndexOutOfBoundsException(endExclusive);
        }
        long result = 0;
        for (int i = endExclusive; i > 0; i -= i & -i) {
            result += tree[i];
        }
        return result;
    }
}
```

Публичный индекс у `add` с нуля, поэтому точка 0 обновляет внутренний индекс 1. Префикс первых k значений использует внутренний индекс k. Границы и суммы предполагаются в допустимом размере памяти и диапазоне long. Для запроса `[l,r)` вычитай префиксы. Метод `add` принимает приращение. Чтобы заменить значение, сохрани прежнее или вычисли разность. Для min двух независимых префиксов аналогичного вычитания нет. Если нужна универсальная ассоциативная агрегация диапазона с точечными обновлениями, рассмотри segment tree.

**Упражнение.** Начни с массива длины 5. Прибавь 4 к индексу 0, 3 к индексу 3 и −2 к индексу 0. Сумма `[0,4)` равна 5, `[1,4)` равна 3, `[4,5)` равна 0. Проверка на пустом диапазоне даёт 0. На собеседовании полезно объяснить, почему индекс 0 во внутреннем цикле не должен встречаться: шаг `0 & -0` равен нулю, цикл перестал бы продвигаться.

## Состояние графа может содержать больше вершины

Робот идёт по клеткам и может убрать максимум одну преграду. Обычный BFS помечает клетку посещённой, когда нашёл кратчайший путь к ней. Здесь два пути к одной клетке могут иметь разную оставшуюся возможность. Состояние должно быть `(row, column, usedRemoval)`. Достигнув клетки с уже использованным удалением, ты ещё не знаешь лучший путь к той же клетке со свободным удалением. Если слить состояния в один visited, подходящая дорога потеряется.

Построй граф состояний. Из клетки можно перейти в соседнюю свободную, сохранив флаг. При переходе в преграду разрешено сменить неиспользованный флаг на использованный. Каждый шаг имеет цену 1, поэтому обычный BFS на новом графе найдёт минимум. Число состояний не больше двух на клетку, выходов не больше четырёх на состояние, время и память `O(rows × cols)`. Если разрешено удалить до K преград, простой вариант держит `K+1` копий. Оптимизация «оставляй только лучший запас» требует доказательства доминирования, например сравнения при проходе по слоям, иначе более длинный путь с большим запасом может затереть короткий.

### Правило описания состояния

Задай вопрос: если два разных прошлых пути пришли в одно состояние, имеют ли они одинаковые возможности будущих действий и одинаковое значение для ответа? Если нет, добавь недостающее измерение. Оно может быть битом, количеством бесплатных операций, маской уже посещённых объектов или последним выбранным символом. После этого оцени число состояний. Маска из N объектов даёт до `2^N` вариантов. Она полезна при малом N, но тяжела для десятков тысяч объектов. Для разреженных состояний словарь экономит выделение пустой таблицы и несёт цену хеширования.

## Граница дня и окна как задача о состояниях

За неделю надо выбрать дни для запуска тяжёлых фоновых отчётов. Две команды используют общий лимит, каждая задача имеет ценность и длительность. Если задача только одна на день или стоит фиксированный ресурс, простой DP по дням может подойти. Если можно запускать произвольные пересекающиеся интервалы с ценностью, сначала отсортируй их по окончанию и найди предшествующий совместимый интервал бинарным поиском.

Для задачи weighted interval scheduling `best[i]` — максимальная ценность среди первых i интервалов, отсортированных по окончанию. Для интервала i есть два варианта. Пропустить его и взять `best[i-1]`, или взять его ценность и прибавить `best[p(i)]`, где `p(i)` — последний совместимый индекс. Соседние полуоткрытые интервалы совместимы при `endPrev <= startNext`. Тогда сортировка и поиск дают `O(n log n)`, а DP — `O(n)` дополнительной памяти.

Например, есть `[1,3)` с ценностью 5, `[2,4)` с ценностью 7 и `[3,5)` с ценностью 6. Жадный выбор максимальной ценности возьмёт средний интервал и получит 7. Первый и третий совместимы и дают 11. Чтобы восстановить список выбранных интервалов, храни решение или сравни `best` на обратном проходе. При равной сумме задай политику разрешения. Например, предпочитай меньшее число задач или лексикографически устойчивые ID. Это может изменить хранимое состояние.

### Выбор набора с заданной суммой

Для небольшой целевой суммы S и неотрицательных целых весов можно хранить `reachable[s]`. Изначально достижим 0. Для каждого элемента веса w последовательно обновляй от S вниз. Тогда на текущем шаге `reachable[s-w]` находится в состоянии предыдущих элементов. Проход снизу вверх может использовать тот же элемент несколько раз. Общая сложность `O(N×S)`, поэтому задачу называем псевдополиномиальной: значение S может быть огромным при коротком представлении числа. Для набора с ограниченной суммой Java `BitSet` может хранить состояния компактнее. У самого API BitSet нет операции общего сдвига, поэтому обновление потребует явного алгоритма, другой битовой структуры или подходящего представления. Перед оптимизацией измерь реальную плотность достижимых сумм.

[Java SE 17, BitSet](https://docs.oracle.com/en/java/javase/17/docs/api/java.base/java/util/BitSet.html)

## Самопроверка

<details>
<summary>Почему массив префиксов слаб для частых обновлений?</summary>

Изменение одной точки влияет на все следующие префиксы. Дерево Фенвика перекладывает эти зависимости на небольшое число блоков.

</details>

<details>
<summary>При BFS из точки A можно один раз пройти через закрытую дверь. Почему visited по вершине недостаточно?</summary>

Будущие переходы зависят от того, потрачена ли возможность. Добавь флаг в вершину графа состояний. Первый визит к физической точке не завершает другое состояние.

</details>

<details>
<summary>Можно ли всегда взять самую ценную независимую задачу и повторить для оставшихся?</summary>

Она может пересекаться с несколькими задачами, совместимыми между собой. Для взвешенных интервалов отсортируй по концам и сравни варианты «взять» и «пропустить» через DP.

</details>

<details>
<summary>Вес 3 рассматривается один раз. Откуда достижима сумма 6 в первом проходе?</summary>

Вероятно, обновляли достижимость снизу вверх и прочитали состояние суммы 3, созданное тем же элементом. Для каждого элемента 0/1 обходи суммы сверху вниз.

</details>
