## Преобразования и числовые типы

### 01. Почему произведение двух int переполняется при присваивании в long?

<details>
<summary>Ответ и разбор</summary>

Java сначала умножает два `int` и только потом сохраняет результат в `long`. Если число уже переполнилось, широкий тип его не исправит. Напиши `(long) a * b`.

</details>

### 02. Что может сломать компаратор (a, b) -> a - b?

<details>
<summary>Ответ и разбор</summary>

Например, `Integer.MIN_VALUE - 1` переполнится и станет положительным числом. Компаратор ошибочно объявит самое маленькое число большим. Используй `Integer.compare(a, b)`.

</details>

### 03. Почему b += 1 компилируется для byte b, а b = b + 1 требует приведения?

<details>
<summary>Ответ и разбор</summary>

При сложении `byte` превращается в `int`. Запись `b += 1` сама приводит результат обратно к `byte`. Поэтому при переходе с 127 получится −128, хотя код компилируется.

</details>

### 04. Почему 0.1 + 0.2 отличается от 0.3?

<details>
<summary>Ответ и разбор</summary>

Компьютер хранит `double` в двоичном виде. Как одна треть не помещается в конечную десятичную дробь, так и 0,1 не помещается в конечную двоичную. Для денег можно хранить целое число копеек.

</details>

### 05. Чем BigDecimal.equals отличается от compareTo для 1.0 и 1.00?

<details>
<summary>Ответ и разбор</summary>

`compareTo` считает 1,0 и 1,00 одним числом и возвращает 0. `equals` учитывает ещё и число знаков после запятой, поэтому вернёт false. Из-за этого `TreeSet` и `HashSet` могут дать разный размер.

</details>

### 06. Почему BigDecimal.divide иногда выбрасывает ArithmeticException?

<details>
<summary>Ответ и разбор</summary>

У результата 1/3 нет конечной десятичной записи. `divide` без правила округления не знает, где остановиться. Например, попроси два знака и подходящее для задачи округление.

</details>

### 07. Что произойдёт при приведении (int) Double.NaN?

<details>
<summary>Ответ и разбор</summary>

`(int) Double.NaN` даёт 0. Если 0 — допустимый результат, после приведения уже не отличить его от ошибки расчёта. Для проверки используй `Double.isNaN` до приведения.

</details>

### 08. Чем Math.floorMod отличается от % при отрицательном индексе?

<details>
<summary>Ответ и разбор</summary>

`-1 % 5` даёт −1, а `Math.floorMod(-1, 5)` даёт 4. Второй вариант подходит, чтобы шаг назад от начала массива переводил на последний элемент.

</details>

## Выбор метода и типизация

### 09. Почему f(null) неоднозначен при перегрузках f(String) и f(Integer)?

<details>
<summary>Ответ и разбор</summary>

`null` можно передать и в `String`, и в `Integer`. Ни один из типов не подходит лучше другого, поэтому компилятор не выбирает. `f((String) null)` явно выбирает строковый метод.

</details>

### 10. При перегрузках f(long) и f(Integer) какая примет аргумент 1?

<details>
<summary>Ответ и разбор</summary>

Выберется `f(long)`. Число `1` имеет тип `int`, и Java сначала пробует расширить его до `long`. Создание объекта `Integer` рассматривается на следующем шаге.

</details>

### 11. Может ли класс объявить одновременно `m(List<String>)` и `m(List<Integer>)`?

<details>
<summary>Ответ и разбор</summary>

Нет. После проверки обобщений оба параметра имеют одну форму `List`. Для JVM получится две одинаковые сигнатуры. Дай методам разные имена или используй один метод с явным правилом.

</details>

### 12. Почему `String[]` присваивается `Object[]`, а `List<String>` не присваивается `List<Object>`?

<details>
<summary>Ответ и разбор</summary>

`String[]` можно передать как `Object[]`, но попытка положить туда число упадёт при записи. Для списков Java заранее запрещает такую подстановку. Читать строки как объекты можно через `List<?>`.

</details>

### 13. В каком случае вызов через raw List отложит ошибку до чтения?

<details>
<summary>Ответ и разбор</summary>

Сырой тип `List` написан без параметра элемента. Через него можно положить число в список строк с предупреждением компилятора. Когда другой код попытается прочитать это число как строку, он получит `ClassCastException`.

</details>

### 14. Когда параметр `<T>` нужен вместо wildcard `?`?

<details>
<summary>Ответ и разбор</summary>

`T` связывает несколько частей метода. Например, метод принимает `List<T>` и возвращает элемент типа `T`. `?` подходит, если метод просто считает элементы и ему всё равно, какого они типа.

</details>

### 15. Как поменять местами элементы в `List<?>`?

<details>
<summary>Ответ и разбор</summary>

Передай список в метод с параметром `List<T>`. Внутри сохрани первый элемент в переменной `T`, поставь на его место второй и запиши первый обратно. Метод работает с тем же неизвестным типом на чтении и записи.

</details>

### 16. Что означает граница `<T extends Comparable<? super T>>`?

<details>
<summary>Ответ и разбор</summary>

Тип `T` должен уметь сравниваться с собой или с более общим типом. Например, подкласс может унаследовать `Comparable` для родительского класса и всё равно подходить для сортировки.

</details>

## Инициализация, строки и время

### 17. Почему опасно вызывать переопределяемый метод из конструктора?

<details>
<summary>Ответ и разбор</summary>

Конструктор родителя может вызвать версию метода из подкласса. Поля подкласса в этот момент ещё не настроены. Например, метод попытается взять длину списка, который пока равен `null`.

</details>

### 18. Когда инициализация интерфейса нужна для чтения константы?

<details>
<summary>Ответ и разбор</summary>

Для простой константы вроде `int LIMIT = 10` число может попасть прямо в код клиента, и интерфейс не начнёт инициализацию. Если значение вычисляется методом, чтение такого поля запускает инициализацию.

</details>

### 19. Что увидит старый клиент после замены JAR с изменённой public static final константой?

<details>
<summary>Ответ и разбор</summary>

Клиент может продолжить показывать старое число, если компилятор вставил его в байткод. Тогда замены JAR недостаточно, нужно пересобрать клиента. Если значение должно меняться между версиями, его можно выдавать методом.

</details>

### 20. Почему length() строки не совпадает с числом символов в emoji?

<details>
<summary>Ответ и разбор</summary>

`length()` считает части UTF-16, а один emoji может занять две части. `codePointCount` считает кодовые точки. Видимый значок иногда состоит даже из нескольких таких точек, например флаг.

</details>

### 21. Почему toLowerCase() ломает ключи при смене локали?

<details>
<summary>Ответ и разбор</summary>

Правила нижнего регистра зависят от языка. Например, в турецкой локали заглавная I может превратиться в букву без точки. Для технических ключей используй `Locale.ROOT`.

</details>

### 22. Почему String.split(".") даёт неожиданный результат?

<details>
<summary>Ответ и разбор</summary>

`split` читает аргумент как регулярное выражение, где точка означает «любой символ». Чтобы делить строку `a.b` по самой точке, передай `Pattern.quote(".")`.

</details>

### 23. Как сохранить пустой последний столбец при split?

<details>
<summary>Ответ и разбор</summary>

По умолчанию пустой элемент в конце отбрасывается. `"a,b,".split(",", -1)` оставит три значения, включая пустое. Для CSV с кавычками нужна отдельная обработка.

</details>

### 24. Почему charset нужен явно при чтении файла партнёра?

<details>
<summary>Ответ и разбор</summary>

Один и тот же набор байтов может означать разные буквы в разных кодировках. Если партнёр присылает UTF-8, укажи UTF-8 явно. Иначе на другой машине русские буквы могут читаться неправильно.

</details>

### 25. Чем Instant отличается от LocalDateTime для времени заказа?

<details>
<summary>Ответ и разбор</summary>

`Instant` задаёт точный момент, например 10:00 UTC. `LocalDateTime` задаёт дату и местное время без указания зоны. Запись «10:00» в Москве и Лондоне может означать разные моменты.

</details>

### 26. Почему «плюс сутки» иногда отличается от «плюс 24 часа»?

<details>
<summary>Ответ и разбор</summary>

При переводе часов календарные сутки могут длиться 23 или 25 часов. «Завтра в 10:00» сохраняет местное время, а «через 24 часа» отсчитывает ровно 24 часа.

</details>

### 27. Зачем внедрять Clock вместо прямого Instant.now()?

<details>
<summary>Ответ и разбор</summary>

Передай объект `Clock` в код, который проверяет срок. Тогда тест может установить часы на 12:00 и проверить истечение точно в 12:01 без реального ожидания.

</details>

## Ошибки и проектирование типов

### 28. Почему return внутри finally опасен?

<details>
<summary>Ответ и разбор</summary>

Если `try` возвращает 1, а `finally` возвращает 2, итогом станет 2. Такой `return` может даже скрыть исключение из `try`. Оставляй `finally` для уборки ресурсов.

</details>

### 29. Что произойдёт при исключении во втором инициализаторе try-with-resources?

<details>
<summary>Ответ и разбор</summary>

Если первый файл открылся, а второй нет, Java закроет первый. Тело `try` не запустится. Если закрытие тоже упало, эта дополнительная ошибка прикрепится к исходной.

</details>

### 30. Зачем сохранять cause при обёртке IOException?

<details>
<summary>Ответ и разбор</summary>

Клиенту полезно знать, что не удалось загрузить отчёт, а разработчику — что файл отсутствует. Передай исходное исключение как причину, чтобы в журнале осталось и сообщение операции, и место сбоя.

</details>

### 31. Почему catch (Exception) с возвратом пустого списка вреден?

<details>
<summary>Ответ и разбор</summary>

Пустой список может честно означать «заказов нет». Если БД недоступна и код тоже вернул пустой список, клиент решит, что всё в порядке. Передай ошибку отдельно.

</details>

### 32. Когда копировать массив, переданный в конструктор?

<details>
<summary>Ответ и разбор</summary>

Если объект должен сохранить снимок данных, скопируй входной массив. Иначе вызывающий может поменять его после конструктора, и объект увидит изменение. Возвращай копию и при чтении, если нужна защита с обеих сторон.

</details>

### 33. Как equals у record сравнит два компонента типа byte[]?

<details>
<summary>Ответ и разбор</summary>

Два отдельных массива с одинаковыми байтами считаются разными ссылками. Обычный record использует это сравнение для массива. Для равенства по содержимому нужны согласованные `Arrays.equals` и `Arrays.hashCode` или другой тип данных.

</details>

### 34. Как sealed-интерфейс помогает представить результат платежа?

<details>
<summary>Ответ и разбор</summary>

Можно разрешить только `Success`, `Declined` и `Pending`. Успех хранит ID оплаты, отказ — причину, ожидание — номер заявки. Так у каждого результата есть только подходящие ему поля.

</details>

### 35. Может ли public метод вернуть private вложенный тип?

<details>
<summary>Ответ и разбор</summary>

Да, Java позволяет такую сигнатуру. Но клиент снаружи не сможет нормально назвать скрытый тип. Если метод предназначен для других классов, лучше вернуть доступный интерфейс.

</details>

### 36. Почему enum.ordinal плох для колонки статуса?

<details>
<summary>Ответ и разбор</summary>

`ordinal()` — позиция в списке констант. Если вставить новый статус перед `PAID`, его номер изменится, и старое число в БД может начать означать другое. Храни стабильное имя или код.

</details>

### 37. Когда java.lang.Class.cast полезнее unchecked приведения?

<details>
<summary>Ответ и разбор</summary>

Когда ожидаемый тип передают параметром, например `String.class`, `cast` проверяет объект по этому типу. Он может сразу отклонить число вместо строки. Проверка класса списка не проверяет тип каждого элемента.

</details>

### 38. Зачем использовать Duration вместо long timeout?

<details>
<summary>Ответ и разбор</summary>

`Duration.ofSeconds(5)` прямо показывает единицы. В `timeout = 5` трудно понять, это миллисекунды или секунды. При переводе в формат клиента проверь нужную точность и диапазон.

</details>

### 39. Почему сравнение времени через currentTimeMillis опасно для таймаута?

<details>
<summary>Ответ и разбор</summary>

`currentTimeMillis` показывает настенные часы, которые могут сдвинуться. Для измерения прошедшего времени бери разность двух `nanoTime()`. Для времени создания заказа всё равно нужны обычные часы.

</details>

### 40. Как задать правило null для коллекции в публичном API?

<details>
<summary>Ответ и разбор</summary>

Напиши в контракте, допустимы ли `null` вместо списка и `null` внутри списка. Например, API может всегда возвращать пустой список для «нет заказов». При частичном обновлении отсутствие поля и пустой список могут означать разные действия.

</details>
