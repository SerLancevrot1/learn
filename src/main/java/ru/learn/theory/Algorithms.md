1. **Короткий ответ** — как распознать приём и что сказать вслух за 30–60 секунд.
2. **Подробности** — под спойлером `<details>`: код, сложность, инвариант.
3. **Уточняющие вопросы** — то, что интервьюер спросит следом.
4. **Практика** — задача с ожидаемым ответом. Сначала решите сами, потом откройте решение.

Отмечайте уверенность прямо в файле:

- `[ ]` — не знаю;
- `[~]` — решаю с подсказкой;
- `[x]` — решаю сам и объясняю сложность.

Повторяйте прежде всего то, что отмечено `[ ]` и `[~]`.

## 1. Как решать задачу на собеседовании

`[ ]` **Короткий ответ:** интервьюер оценивает не только код, но и ход мысли. Порядок: уточнить условие → назвать простое решение и его сложность → найти узкое место → улучшить → написать код → прогнать на примере и граничных случаях.

### Пять шагов

1. **Уточнить вход.** Размер `n`, диапазон значений, могут ли быть отрицательные числа, дубликаты, пустой вход. Отсортирован ли массив. Можно ли менять вход.
2. **Назвать перебор.** Даже если он медленный: «Перебор пар — `O(n²)`». Это показывает, что вы понимаете задачу.
3. **Найти, что повторяется.** Повторный поиск → хеш-таблица. Повторная сумма отрезка → префиксные суммы. Повторное сравнение с уже просмотренным → стек или куча.
4. **Написать код и проговорить инвариант:** «В карте лежат все числа левее `i`».
5. **Проверить вручную** на маленьком примере и на граничных случаях.

### Признак в условии → приём

| Признак | Что попробовать | Раздел |
|---|---|---|
| Массив отсортирован; пара, граница, позиция | Два указателя, бинарный поиск | [3](#3-два-указателя), [6](#6-бинарный-поиск) |
| Непрерывный подмассив или подстрока | Скользящее окно, префиксные суммы | [4](#4-скользящее-окно), [5](#5-префиксные-суммы) |
| Наличие, частоты, дубликаты | `HashMap` / `HashSet` | [2](#2-хеш-таблицы) |
| Следующий больший или меньший элемент | Монотонный стек | [8](#8-стек-и-монотонные-структуры) |
| k наибольших или наименьших | Куча | [12](#12-куча-и-top-k) |
| Кратчайший путь без весов | BFS | [11](#11-графы) |
| Все комбинации, перестановки | Backtracking | [13](#13-backtracking) |
| Ответ из ответов на меньшие подзадачи | DP | [14](#14-динамическое-программирование) |
| Связность, объединение групп | Union-Find (DSU) | [11](#11-графы) |
| «Минимальное X, при котором можно…» | Бинарный поиск по ответу | [Задача 8](#задача-8-минимальная-скорость) |
| Локально лучший выбор кажется верным | Жадный алгоритм — но с обоснованием | [14](#14-динамическое-программирование) |

### Сложность и ограничения

| Сложность | Пример | Обычно подходит для `n` до |
|---|---|---|
| `O(1)`, `O(log n)` | доступ по индексу, бинарный поиск | любого |
| `O(n)` | один проход | ~10⁷–10⁸ |
| `O(n log n)` | сортировка | ~10⁶ |
| `O(n²)` | все пары | ~10³–10⁴ |
| `O(2ⁿ)`, `O(n!)` | подмножества, перестановки | ~20 и ~10 |

<details>
<summary>Подробности: как не ошибиться в оценке</summary>

- Два вложенных цикла — не всегда `O(n²)`. Если внутренний указатель только движется вперёд и за всё время проходит массив один раз, суммарно это `O(n)` (амортизированный анализ).
- Считайте и память: хеш-таблица — `O(n)`, рекурсия — `O(глубина)`. На вырожденном дереве глубина равна `n`.
- Ожидаемое `O(1)` у `HashMap` — это среднее. При большом числе коллизий в одной корзине Java превращает её в дерево, и худший случай для неё — `O(log n)`.
- Ограничения подсказывают ответ: `n ≤ 20` намекает на перебор подмножеств, `n ≤ 10⁵` — на `O(n log n)`.

</details>

**Типичная ошибка:** сразу писать код, не проговорив подход. Если интервьюер увидит ошибку в идее через 15 минут кода, времени на исправление не останется.

## 2. Хеш-таблицы

`[ ]` **Короткий ответ:** если вы много раз ищете элемент среди уже просмотренных или считаете частоты, замените повторный перебор на `HashMap` или `HashSet`. Это меняет `O(n²)` на `O(n)` ценой `O(n)` памяти.

```java
Map<Integer, Integer> count = new HashMap<>();
for (int x : nums) count.merge(x, 1, Integer::sum);
```

- «Значение → частота»: повторы, анаграммы, элементы с заданной частотой.
- «Значение → индекс»: Two Sum и похожие задачи.
- Для маленького фиксированного алфавита массив `int[26]` проще и быстрее карты.

### Задача 1. Two Sum

`[ ]` Дан массив и число `target`. Верните индексы двух разных элементов с суммой `target`.

Ожидаемый результат: `[2,7,11,15], 9 → [0, 1]`; `[3,3], 6 → [0, 1]`.

<details>
<summary>Решение</summary>

```java
static int[] twoSum(int[] nums, int target) {
    Map<Long, Integer> indexByValue = new HashMap<>();
    for (int i = 0; i < nums.length; i++) {
        long need = (long) target - nums[i];
        Integer j = indexByValue.get(need);
        if (j != null) return new int[] { j, i };
        indexByValue.put((long) nums[i], i);
    }
    return new int[0];
}
```

Время `O(n)`, память `O(n)`. Инвариант: в карте лежат все числа левее `i`.

</details>

**Уточнение интервьюера:** «Почему сначала проверка, а потом `put`?»

<details>
<summary>Ответ</summary>

Чтобы не использовать один элемент дважды. Для `[3, 5]` и `target = 6` при обратном порядке число 3 нашло бы само себя. И наоборот, для `[3, 3]` именно проверка до вставки находит пару `[0, 1]`.

`long` нужен потому, что `target - nums[i]` может выйти за пределы `int`. Один вызов `get` вместо `containsKey` + `get` — меньше обращений к карте.

</details>

**Уточнение интервьюера:** «А если массив отсортирован?» — тогда два указателя за `O(n)` и `O(1)` памяти, см. [3](#3-два-указателя).

### Задача 2. Максимальная сумма подмассива

`[ ]` Найдите максимальную сумму непустого непрерывного подмассива (алгоритм Кадане).

Ожидаемый результат: `[-2,1,-3,4,-1,2,1,-5,4] → 6`; `[-3,-1,-2] → -1`.

<details>
<summary>Решение</summary>

```java
static int maxSubArray(int[] nums) {
    int current = nums[0], best = nums[0];
    for (int i = 1; i < nums.length; i++) {
        current = Math.max(nums[i], current + nums[i]); // продолжить или начать заново
        best = Math.max(best, current);
    }
    return best;
}
```

`current` — лучшая сумма отрезка, который **заканчивается** в `i`. Время `O(n)`, память `O(1)`. Это DP с одним состоянием.

</details>

**Типичная ошибка:** инициализировать `current` и `best` нулём. Для массива из отрицательных чисел ответ станет `0`, хотя подмассив должен быть непустым.

## 3. Два указателя

`[ ]` **Короткий ответ:** два индекса, которые двигаются по массиву по правилу. Навстречу — для отсортированного массива и сравнения концов. В одну сторону («читатель» и «писатель») — для изменения массива на месте. Медленный и быстрый — для циклов и середины списка.

```java
int left = 0, right = nums.length - 1;
while (left < right) {
    long sum = (long) nums[left] + nums[right];
    if (sum == target) break;
    if (sum < target) left++;   // нужна сумма больше
    else right--;               // нужна сумма меньше
}
```

Обоснуйте каждое движение: почему отброшенные варианты уже не могут быть ответом. Здесь: если `sum < target`, то `nums[left]` с любым элементом левее `right` даст ещё меньше.

### Задача 3. Удалить дубликаты на месте

`[ ]` Отсортированный массив. Оставьте каждое значение один раз в начале массива и верните новую длину.

Ожидаемый результат: `[1,1,2,3,3] → 3`, начало массива `[1,2,3]`.

<details>
<summary>Решение</summary>

```java
static int removeDuplicates(int[] nums) {
    if (nums.length == 0) return 0;
    int write = 1;
    for (int read = 1; read < nums.length; read++) {
        if (nums[read] != nums[write - 1]) nums[write++] = nums[read];
    }
    return write;
}
```

Инвариант: `nums[0..write)` — уникальные значения в исходном порядке. Время `O(n)`, память `O(1)`.

</details>

### Задача 4. Слить отсортированные массивы в первый

`[ ]` `a` длиной `m + n`, в начале `m` отсортированных чисел, в конце свободное место. `b` — `n` отсортированных чисел. Слейте `b` в `a`.

Ожидаемый результат: `a=[1,2,3,0,0,0], b=[2,5,6] → [1,2,2,3,5,6]`.

<details>
<summary>Решение</summary>

```java
static void mergeInto(int[] a, int m, int[] b, int n) {
    int i = m - 1, j = n - 1, k = m + n - 1;
    while (j >= 0) a[k--] = (i >= 0 && a[i] > b[j]) ? a[i--] : b[j--];
}
```

Заполняем **справа налево**, чтобы не затереть ещё не прочитанные элементы `a`. Цикл идёт, пока не кончится `b`: остаток `a` уже стоит на своём месте.

</details>

## 4. Скользящее окно

`[ ]` **Короткий ответ:** для непрерывного участка. Правый край расширяет окно, левый сужает, пока окно нарушает условие. Каждый край проходит массив один раз, поэтому `O(n)`, хотя циклов два.

```java
int left = 0;
for (int right = 0; right < nums.length; right++) {
    // добавить nums[right] в состояние окна
    while (/* окно нарушает условие */) {
        // убрать nums[left] из состояния
        left++;
    }
    // обновить ответ по окну [left, right]
}
```

Окно работает, только если условие **монотонно**: расширение окна ухудшает его в одну сторону, сужение — улучшает.

### Задача 5. Самая длинная подстрока без повторов

`[ ]` Найдите длину самой длинной подстроки без повторяющихся символов.

Ожидаемый результат: `"abcabcbb" → 3`; `"abba" → 2`.

<details>
<summary>Решение</summary>

```java
static int lengthOfLongestSubstring(String s) {
    Map<Character, Integer> last = new HashMap<>();
    int left = 0, best = 0;
    for (int right = 0; right < s.length(); right++) {
        char c = s.charAt(right);
        Integer prev = last.get(c);
        if (prev != null && prev >= left) left = prev + 1;
        last.put(c, right);
        best = Math.max(best, right - left + 1);
    }
    return best;
}
```

</details>

**Типичная ошибка:** писать `left = prev + 1` без проверки `prev >= left`. На `"abba"` левый край прыгнет **назад** (на второй `a` он вернётся к индексу 1), и ответ будет 3 вместо 2.

<details>
<summary>Ещё одна задача: минимальное окно с суммой не меньше target</summary>

Только неотрицательные числа. `7, [2,3,1,2,4,3] → 2` (подмассив `[4,3]`).

```java
static int minSubArrayLen(int target, int[] nums) {
    int left = 0, best = Integer.MAX_VALUE;
    long sum = 0;
    for (int right = 0; right < nums.length; right++) {
        sum += nums[right];
        while (sum >= target) {
            best = Math.min(best, right - left + 1);
            sum -= nums[left++];
        }
    }
    return best == Integer.MAX_VALUE ? 0 : best;
}
```

</details>

## 5. Префиксные суммы

`[ ]` **Короткий ответ:** `prefix[i]` — сумма первых `i` элементов. Сумма отрезка `[l, r]` = `prefix[r + 1] - prefix[l]` за `O(1)` после `O(n)` подготовки. В паре с хеш-таблицей решает задачи о подмассивах с заданной суммой, в том числе с отрицательными числами.

```text
prefix[0] = 0
prefix[i + 1] = prefix[i] + nums[i]
sum(l..r) = prefix[r + 1] - prefix[l]
```

### Задача 6. Количество подмассивов с суммой k

`[ ]` Посчитайте число непрерывных подмассивов с суммой `k`. Числа могут быть отрицательными.

Ожидаемый результат: `[1,1,1], k=2 → 2`; `[1,-1,0], k=0 → 3`.

<details>
<summary>Решение</summary>

```java
static long subarraySum(int[] nums, int k) {
    Map<Long, Integer> seen = new HashMap<>();
    seen.put(0L, 1);                 // пустой префикс
    long prefix = 0, answer = 0;
    for (int x : nums) {
        prefix += x;
        answer += seen.getOrDefault(prefix - k, 0);
        seen.merge(prefix, 1, Integer::sum);
    }
    return answer;
}
```

Отрезок `(j, i]` имеет сумму `k`, если `prefix[i] - prefix[j] = k`, то есть мы ищем, сколько раз раньше встречался префикс `prefix - k`. Время `O(n)`, память `O(n)`.

</details>

**Уточнение интервьюера:** «Почему здесь нельзя скользящее окно?»

<details>
<summary>Ответ</summary>

Из-за отрицательных чисел. Окно опирается на монотонность: добавили элемент — сумма выросла, убрали — уменьшилась. С отрицательными числами расширение окна может уменьшить сумму, и правило «сужай, пока сумма больше k» теряет ответы. На `[1,-1,0], k=0` правильных подмассивов три: `[1,-1]`, `[-1,0]` и `[1,-1,0]`, — окно их не найдёт.

</details>

**Типичная ошибка:** забыть `seen.put(0L, 1)`. Тогда не посчитаются подмассивы, которые начинаются с индекса 0.

## 6. Бинарный поиск

`[ ]` **Короткий ответ:** бинарный поиск работает на любом **монотонном** условии, а не только на поиске элемента. Чаще всего на собеседовании нужен не «найти элемент», а «найти границу»: первый индекс, где условие истинно.

Два шаблона, которые нельзя смешивать:

| Шаблон | Интервал | Условие цикла | Сдвиг |
|---|---|---|---|
| Поиск элемента | `[left, right]` закрытый | `left <= right` | `left = mid + 1`, `right = mid - 1` |
| Поиск границы | `[left, right)` полуоткрытый | `left < right` | `left = mid + 1`, `right = mid` |

Середина: `left + (right - left) / 2`. Запись `(left + right) / 2` переполняет `int` на больших индексах (проверено: при `left = Integer.MAX_VALUE - 2`, `right = Integer.MAX_VALUE` результат отрицательный).

### Задача 7. Первое и последнее вхождение

`[ ]` Отсортированный массив с повторами. Найдите первый индекс `>= target` (lower bound), первый индекс `> target` (upper bound) и число вхождений.

Ожидаемый результат для `[1,2,2,2,5,7]`, `target=2`: `lower=1`, `upper=4`, вхождений 3. Для `target=100`: `lower=6` (длина массива).

<details>
<summary>Решение</summary>

```java
static int lowerBound(int[] nums, int target) {
    int left = 0, right = nums.length;          // [left, right)
    while (left < right) {
        int mid = left + (right - left) / 2;
        if (nums[mid] < target) left = mid + 1;
        else right = mid;
    }
    return left;                                 // может быть nums.length
}

static int upperBound(int[] nums, int target) {
    int left = 0, right = nums.length;
    while (left < right) {
        int mid = left + (right - left) / 2;
        if (nums[mid] <= target) left = mid + 1; // единственное отличие: <=
        else right = mid;
    }
    return left;
}
```

Число вхождений — `upperBound - lowerBound`. Время `O(log n)`.

</details>

**Уточнение интервьюера:** «А что вернёт `Arrays.binarySearch`, если элемента нет?»

<details>
<summary>Ответ</summary>

`-(insertion point) - 1`, где точка вставки — индекс первого элемента больше ключа. Точку вставки восстанавливают как `-result - 1` ([Collections.binarySearch, Java SE](https://download.java.net/java/early_access/loom/docs/api/java.base/java/util/Collections.html)). При дубликатах стандартный метод не гарантирует, какое из вхождений найдёт, поэтому для границ пишут свой lower bound.

</details>

### Задача 8. Минимальная скорость

`[ ]` Кучки бананов `piles`, есть `h` часов. За час можно съесть до `k` бананов из одной кучки. Найдите минимальное `k`, чтобы успеть.

Ожидаемый результат: `[3,6,7,11], h=8 → 4`.

<details>
<summary>Подсказка</summary>

Если скорость `k` подходит, то подходит и любая большая. Это монотонное условие — ищите первую подходящую скорость в диапазоне `[1, max(piles)]`.

</details>

<details>
<summary>Решение</summary>

```java
static int minEatingSpeed(int[] piles, int h) {
    int lo = 1, hi = Arrays.stream(piles).max().orElse(1);
    while (lo < hi) {
        int mid = lo + (hi - lo) / 2;
        if (hoursNeeded(piles, mid) <= h) hi = mid; // подходит — ищем меньше
        else lo = mid + 1;
    }
    return lo;
}

static long hoursNeeded(int[] piles, int speed) {
    long hours = 0;
    for (int p : piles) hours += (p + speed - 1) / speed; // деление с округлением вверх
    return hours;
}
```

Время `O(n log max)`. Шаблон «поиск по ответу»: диапазон ответа → проверка `can(x)` → направление сдвига → граничные случаи.

</details>

## 7. Сортировка и интервалы

`[ ]` **Короткий ответ:** если порядок обработки упрощает задачу, сначала отсортируйте — `O(n log n)`. Для интервалов почти всегда сортируют по началу.

### Задача 9. Слияние интервалов

`[ ]` Объедините пересекающиеся интервалы.

Ожидаемый результат: `[[8,10],[1,3],[2,6],[15,18]] → [[1,6],[8,10],[15,18]]`; `[[1,4],[4,5]] → [[1,5]]`.

<details>
<summary>Решение</summary>

```java
static int[][] merge(int[][] intervals) {
    int[][] sorted = intervals.clone();
    Arrays.sort(sorted, Comparator.comparingInt(a -> a[0]));
    List<int[]> result = new ArrayList<>();
    for (int[] cur : sorted) {
        if (!result.isEmpty() && cur[0] <= result.get(result.size() - 1)[1]) {
            int[] last = result.get(result.size() - 1);
            last[1] = Math.max(last[1], cur[1]);   // max: [1,10] поглощает [2,3]
        } else {
            result.add(new int[] { cur[0], cur[1] });
        }
    }
    return result.toArray(new int[0][]);
}
```

</details>

**Уточнение интервьюера:** «Касающиеся интервалы пересекаются?» — это нужно спросить. От ответа зависит `<=` или `<`. В решении выше `[1,4]` и `[4,5]` сливаются.

**Типичная ошибка:** `last[1] = cur[1]` вместо `Math.max`. Интервал `[2,3]` внутри `[1,10]` укоротит результат до `[1,3]`.

### Задача 10. Сколько нужно переговорных

`[ ]` Даны встречи `[start, end)`. Найдите минимальное число комнат.

Ожидаемый результат: `[[0,30],[5,10],[15,20]] → 2`; `[[1,5],[5,10]] → 1`.

<details>
<summary>Решение</summary>

```java
static int minMeetingRooms(int[][] intervals) {
    int[][] sorted = intervals.clone();
    Arrays.sort(sorted, Comparator.comparingInt(a -> a[0]));
    PriorityQueue<Integer> ends = new PriorityQueue<>();   // концы занятых комнат
    for (int[] m : sorted) {
        if (!ends.isEmpty() && ends.peek() <= m[0]) ends.poll(); // комната освободилась
        ends.add(m[1]);
    }
    return ends.size();
}
```

Время `O(n log n)`. Альтернатива: отдельно отсортировать начала и концы и пройти двумя указателями.

</details>

## 8. Стек и монотонные структуры

`[ ]` **Короткий ответ:** стек — для вложенности и «последнего незакрытого». Монотонный стек хранит индексы в возрастающем или убывающем порядке и находит «следующий больший/меньший» за `O(n)`: каждый индекс один раз кладётся и один раз снимается. Монотонная очередь (дек) даёт максимум в скользящем окне за `O(n)`.

В Java для стека и очереди используйте `ArrayDeque`, а не устаревший `Stack` и не `LinkedList`. `ArrayDeque` не потокобезопасен и не принимает `null` ([ArrayDeque, Java SE 25](https://ligm.univ-eiffel.fr/~juge/javadoc-25/api/java.base/java/util/ArrayDeque.html)).

### Задача 11. Правильные скобки

`[ ]` Строка из `()[]{}`. Проверьте, что скобки сбалансированы.

Ожидаемый результат: `"({[]})" → true`, `"(]" → false`, `"((" → false`.

<details>
<summary>Решение</summary>

```java
static boolean isValid(String s) {
    Deque<Character> stack = new ArrayDeque<>();
    for (char c : s.toCharArray()) {
        switch (c) {
            case '(' -> stack.push(')');   // кладём ожидаемую закрывающую
            case '[' -> stack.push(']');
            case '{' -> stack.push('}');
            default -> { if (stack.isEmpty() || stack.pop() != c) return false; }
        }
    }
    return stack.isEmpty();               // без этой проверки "((" пройдёт
}
```

</details>

### Задача 12. До более тёплого дня

`[ ]` Для каждого дня найдите, через сколько дней станет теплее. Если не станет — `0`.

Ожидаемый результат: `[73,74,75,71,69,72,76,73] → [1,1,4,2,1,1,0,0]`.

<details>
<summary>Решение</summary>

```java
static int[] dailyTemperatures(int[] t) {
    int[] answer = new int[t.length];
    Deque<Integer> stack = new ArrayDeque<>();      // индексы, температуры убывают
    for (int i = 0; i < t.length; i++) {
        while (!stack.isEmpty() && t[stack.peek()] < t[i]) {
            int j = stack.pop();                    // для j нашёлся ответ
            answer[j] = i - j;
        }
        stack.push(i);
    }
    return answer;
}
```

</details>

**Уточнение интервьюера:** «Почему это `O(n)`, если внутри `while`?» — каждый индекс кладётся в стек один раз и снимается не больше одного раза. Всего не больше `2n` операций.

### Задача 13. Максимум в каждом окне

`[ ]` Найдите максимум в каждом окне длины `k`.

Ожидаемый результат: `[1,3,-1,-3,5,3,6,7], k=3 → [3,3,5,5,6,7]`.

<details>
<summary>Решение</summary>

```java
static int[] maxSlidingWindow(int[] nums, int k) {
    int[] result = new int[nums.length - k + 1];
    Deque<Integer> dq = new ArrayDeque<>();               // индексы, значения убывают
    for (int i = 0; i < nums.length; i++) {
        if (!dq.isEmpty() && dq.peekFirst() <= i - k) dq.pollFirst();      // вышел из окна
        while (!dq.isEmpty() && nums[dq.peekLast()] <= nums[i]) dq.pollLast(); // хуже нового
        dq.addLast(i);
        if (i >= k - 1) result[i - k + 1] = nums[dq.peekFirst()];
    }
    return result;
}
```

Время `O(n)`, память `O(k)`. С кучей было бы `O(n log n)`.

</details>

## 9. Связные списки

`[ ]` **Короткий ответ:** почти все задачи решаются тремя приёмами: перенаправление ссылок с сохранением `next`, фиктивный узел `dummy` и медленный/быстрый указатели. Перед изменением `current.next` всегда сохраняйте следующий узел.

```java
static final class ListNode { int val; ListNode next; ListNode(int v) { val = v; } }
```

### Задача 14. Разворот списка

`[ ]` Разверните односвязный список. Ожидаемый результат: `1→2→3→4 → 4→3→2→1`.

<details>
<summary>Решение</summary>

```java
static ListNode reverse(ListNode head) {
    ListNode prev = null, current = head;
    while (current != null) {
        ListNode next = current.next;  // сохранить хвост
        current.next = prev;           // развернуть ссылку
        prev = current;
        current = next;
    }
    return prev;
}
```

Время `O(n)`, память `O(1)`. Рекурсивный вариант тратит `O(n)` стека.

</details>

### Задача 15. Начало цикла в списке

`[ ]` Верните узел, с которого начинается цикл, или `null`.

Ожидаемый результат: `1→2→3→4→5→(обратно на 3)` → узел `3`; `1→2→3` → `null`.

<details>
<summary>Решение</summary>

```java
static ListNode cycleStart(ListNode head) {
    ListNode slow = head, fast = head;
    while (fast != null && fast.next != null) {   // проверка до fast.next.next
        slow = slow.next;
        fast = fast.next.next;
        if (slow == fast) {                        // встретились внутри цикла
            ListNode p = head;
            while (p != slow) { p = p.next; slow = slow.next; }
            return p;                              // вход в цикл
        }
    }
    return null;
}
```

</details>

**Уточнение интервьюера:** «Почему второй проход находит именно вход в цикл?»

<details>
<summary>Ответ</summary>

Пусть до входа в цикл `a` шагов, от входа до точки встречи `b`, длина цикла `c`. К встрече медленный прошёл `a + b`, быстрый — вдвое больше, `2(a + b)`. Разница `a + b` кратна `c`. Значит, от точки встречи до входа `a` шагов по модулю `c` — столько же, сколько от головы. Два указателя, идущие по одному шагу, встретятся на входе.

</details>

<details>
<summary>Ещё одна задача: слияние двух отсортированных списков</summary>

`1→3→5` и `2→4→6` → `1→2→3→4→5→6`.

```java
static ListNode mergeTwo(ListNode a, ListNode b) {
    ListNode dummy = new ListNode(0), tail = dummy;  // dummy избавляет от особого случая головы
    while (a != null && b != null) {
        if (a.val <= b.val) { tail.next = a; a = a.next; }
        else { tail.next = b; b = b.next; }
        tail = tail.next;
    }
    tail.next = (a != null) ? a : b;
    return dummy.next;
}
```

</details>

## 10. Деревья

`[ ]` **Короткий ответ:** DFS (рекурсия) — когда ответ строится из ответов поддеревьев. BFS (очередь) — когда важны уровни или ближайший узел. Порядки DFS: preorder (узел → левое → правое), inorder (левое → узел → правое, в BST даёт возрастание), postorder (дети → узел, когда нужен ответ детей).

```java
static final class TreeNode { int val; TreeNode left, right; }
```

На вырожденном дереве (по сути списке) глубина рекурсии — `n`. При `n` порядка 10⁵ возможен `StackOverflowError`; тогда нужен итеративный обход.

### Задача 16. Обход по уровням

`[ ]` Верните значения дерева по уровням. Для дерева `3 → (9, 20 → (15, 7))` ожидается `[[3], [9, 20], [15, 7]]`, глубина 3.

<details>
<summary>Решение</summary>

```java
static List<List<Integer>> levelOrder(TreeNode root) {
    List<List<Integer>> result = new ArrayList<>();
    if (root == null) return result;
    Queue<TreeNode> q = new ArrayDeque<>();
    q.add(root);
    while (!q.isEmpty()) {
        int size = q.size();                 // ровно столько узлов на этом уровне
        List<Integer> level = new ArrayList<>();
        for (int i = 0; i < size; i++) {
            TreeNode cur = q.remove();
            level.add(cur.val);
            if (cur.left != null) q.add(cur.left);
            if (cur.right != null) q.add(cur.right);
        }
        result.add(level);
    }
    return result;
}

static int maxDepth(TreeNode root) {
    return root == null ? 0 : 1 + Math.max(maxDepth(root.left), maxDepth(root.right));
}
```

</details>

### Задача 17. Проверка BST

`[ ]` Проверьте, что дерево — корректное дерево поиска.

Ожидаемый результат: `2 → (1, 3)` — `true`; `5 → (1, 6 → (3, 7))` — `false`.

<details>
<summary>Решение</summary>

```java
static boolean isValidBST(TreeNode node, long min, long max) {
    if (node == null) return true;
    if (node.val <= min || node.val >= max) return false;
    return isValidBST(node.left, min, node.val)
        && isValidBST(node.right, node.val, max);
}
// вызов: isValidBST(root, Long.MIN_VALUE, Long.MAX_VALUE)
```

</details>

**Типичная ошибка:** сравнивать узел только с непосредственными детьми. Во втором примере каждый узел корректен относительно своих детей (`3 < 6 < 7`), но `3` лежит в правом поддереве `5` и должен быть больше 5. Нужно передавать вниз допустимый диапазон. Границы типа `long`, чтобы узел со значением `Integer.MIN_VALUE` не ломал проверку.

<details>
<summary>Ещё одна задача: сбалансировано ли дерево</summary>

Проверка за один проход: функция возвращает высоту или `-1`, если поддерево уже несбалансировано. Так высота не пересчитывается многократно (наивный вариант — `O(n²)`).

```java
static int heightOrMinus1(TreeNode node) {
    if (node == null) return 0;
    int l = heightOrMinus1(node.left);  if (l < 0) return -1;
    int r = heightOrMinus1(node.right); if (r < 0) return -1;
    return Math.abs(l - r) > 1 ? -1 : 1 + Math.max(l, r);
}
```

</details>

## 11. Графы

`[ ]` **Короткий ответ:** граф храните списком смежности — `O(V + E)` памяти. Обход без весов — BFS или DFS с массивом посещённых. Кратчайший путь: без весов — BFS, неотрицательные веса — Dijkstra, отрицательные — Bellman–Ford, все пары — Floyd–Warshall. Зависимости — топологическая сортировка. Объединение групп — DSU.

| Задача | Алгоритм | Сложность |
|---|---|---|
| Достижимость, компоненты, острова | BFS / DFS | `O(V + E)` |
| Кратчайший путь, веса одинаковые | BFS | `O(V + E)` |
| Кратчайший путь, веса `>= 0` | Dijkstra с кучей | `O((V + E) log V)` |
| Есть отрицательные веса, поиск отрицательного цикла | Bellman–Ford | `O(V · E)` |
| Кратчайшие пути между всеми парами | Floyd–Warshall | `O(V³)` |
| Порядок с зависимостями, поиск цикла в DAG | Топологическая сортировка (Kahn) | `O(V + E)` |
| Связность при добавлении рёбер, Краскал | DSU | почти `O(1)` на операцию |

### Задача 18. Число островов

`[ ]` Сетка из `'1'` (суша) и `'0'` (вода). Посчитайте острова, соседи — по 4 направлениям.

```text
11000
11000
00100
00011     → 3
```

<details>
<summary>Решение</summary>

```java
static int numIslands(char[][] grid) {
    int rows = grid.length, cols = grid[0].length, count = 0;
    int[] dr = {-1, 1, 0, 0}, dc = {0, 0, -1, 1};
    boolean[][] seen = new boolean[rows][cols];
    for (int r = 0; r < rows; r++) for (int c = 0; c < cols; c++) {
        if (grid[r][c] != '1' || seen[r][c]) continue;
        count++;                                  // новый остров — обойти его целиком
        Deque<int[]> q = new ArrayDeque<>();
        seen[r][c] = true;
        q.add(new int[] { r, c });
        while (!q.isEmpty()) {
            int[] cell = q.remove();
            for (int d = 0; d < 4; d++) {
                int nr = cell[0] + dr[d], nc = cell[1] + dc[d];
                if (nr < 0 || nc < 0 || nr >= rows || nc >= cols) continue;
                if (grid[nr][nc] != '1' || seen[nr][nc]) continue;
                seen[nr][nc] = true;
                q.add(new int[] { nr, nc });
            }
        }
    }
    return count;
}
```

Время `O(rows · cols)`. BFS вместо рекурсивного DFS — чтобы большой остров не переполнил стек.

</details>

### Задача 19. Кратчайший путь в лабиринте

`[ ]` Сетка, `#` — стена. Найдите минимальное число шагов из левого верхнего угла в правый нижний или `-1`.

```text
..#
#..
...       → 4
```

<details>
<summary>Решение</summary>

```java
static int shortestPath(char[][] grid) {
    int rows = grid.length, cols = grid[0].length;
    int[][] dist = new int[rows][cols];
    for (int[] row : dist) Arrays.fill(row, -1);   // -1 = не посещена
    int[] dr = {-1, 1, 0, 0}, dc = {0, 0, -1, 1};
    Deque<int[]> q = new ArrayDeque<>();
    dist[0][0] = 0;
    q.add(new int[] { 0, 0 });
    while (!q.isEmpty()) {
        int[] cell = q.remove();
        for (int d = 0; d < 4; d++) {
            int nr = cell[0] + dr[d], nc = cell[1] + dc[d];
            if (nr < 0 || nc < 0 || nr >= rows || nc >= cols) continue;
            if (grid[nr][nc] == '#' || dist[nr][nc] >= 0) continue;
            dist[nr][nc] = dist[cell[0]][cell[1]] + 1;  // пометка при добавлении
            q.add(new int[] { nr, nc });
        }
    }
    return dist[rows - 1][cols - 1];
}
```

</details>

**Уточнение интервьюера:** «Почему BFS даёт кратчайший путь и почему помечать при добавлении?»

<details>
<summary>Ответ</summary>

Очередь обрабатывает клетки в порядке неубывания расстояния: сначала все на расстоянии 1, потом 2 и так далее. Первое попадание в клетку — по кратчайшему пути.

Если помечать при извлечении, одна клетка успеет попасть в очередь несколько раз от разных соседей. Ответ останется верным, но очередь раздуется, и в плотной сетке время заметно вырастет.

</details>

### Задача 20. Порядок сборки

`[ ]` `n` модулей, ребро `[a, b]` значит «`a` нужно собрать до `b`». Верните порядок или пустой список, если есть цикл.

Ожидаемый результат: `n=4, [[0,1],[0,2],[1,3],[2,3]] → [0,1,2,3]`; `n=3, [[0,1],[1,2],[2,0]] → []`.

<details>
<summary>Решение (алгоритм Кана)</summary>

```java
static List<Integer> topoSort(int n, int[][] edges) {
    List<List<Integer>> g = new ArrayList<>();
    for (int i = 0; i < n; i++) g.add(new ArrayList<>());
    int[] indeg = new int[n];
    for (int[] e : edges) { g.get(e[0]).add(e[1]); indeg[e[1]]++; }
    Deque<Integer> q = new ArrayDeque<>();
    for (int i = 0; i < n; i++) if (indeg[i] == 0) q.add(i);
    List<Integer> order = new ArrayList<>();
    while (!q.isEmpty()) {
        int v = q.remove();
        order.add(v);
        for (int next : g.get(v)) if (--indeg[next] == 0) q.add(next);
    }
    return order.size() == n ? order : List.of();   // не все обработаны — цикл
}
```

</details>

### Задача 21. Dijkstra

`[ ]` Ориентированный граф с неотрицательными весами `[from, to, w]`. Найдите расстояния от вершины 0.

Ожидаемый результат: `n=4, [[0,1,4],[0,2,1],[2,1,2],[1,3,1],[2,3,5]] → [0, 3, 1, 4]`.

<details>
<summary>Решение</summary>

```java
static long[] dijkstra(int n, int[][] edges, int src) {
    List<List<int[]>> g = new ArrayList<>();
    for (int i = 0; i < n; i++) g.add(new ArrayList<>());
    for (int[] e : edges) g.get(e[0]).add(new int[] { e[1], e[2] });
    long[] dist = new long[n];
    Arrays.fill(dist, Long.MAX_VALUE);
    dist[src] = 0;
    PriorityQueue<long[]> pq = new PriorityQueue<>(Comparator.comparingLong(a -> a[1]));
    pq.add(new long[] { src, 0 });
    while (!pq.isEmpty()) {
        long[] top = pq.poll();
        int v = (int) top[0];
        if (top[1] > dist[v]) continue;              // устаревшая запись
        for (int[] e : g.get(v)) {
            long nd = dist[v] + e[1];
            if (nd < dist[e[0]]) {
                dist[e[0]] = nd;
                pq.add(new long[] { e[0], nd });
            }
        }
    }
    return dist;
}
```

У `PriorityQueue` в Java нет операции «уменьшить ключ», поэтому кладут новую запись и пропускают устаревшие.

</details>

**Уточнение интервьюера:** «Почему нельзя с отрицательными весами?»

<details>
<summary>Ответ</summary>

Dijkstra считает расстояние до вершины окончательным, когда достаёт её из кучи: «дешевле уже не будет, все остальные пути длиннее». Отрицательное ребро, найденное позже, может сделать путь короче, но вершина уже закрыта. Для отрицательных весов — Bellman–Ford: `V - 1` раз релаксирует все рёбра, а если на `V`-м проходе что-то ещё улучшилось — есть отрицательный цикл.

</details>

### Задача 22. Union-Find

`[ ]` Реализуйте DSU с объединением по размеру и сжатием путей. Используйте его, чтобы найти ребро, создающее цикл в неориентированном графе.

<details>
<summary>Решение</summary>

```java
static final class DSU {
    final int[] parent, size;
    DSU(int n) {
        parent = new int[n]; size = new int[n];
        for (int i = 0; i < n; i++) { parent[i] = i; size[i] = 1; }
    }
    int find(int x) {
        while (parent[x] != x) {
            parent[x] = parent[parent[x]];   // сжатие пути (вариант «половинное»)
            x = parent[x];
        }
        return x;
    }
    boolean union(int a, int b) {
        int ra = find(a), rb = find(b);
        if (ra == rb) return false;          // уже в одной группе → ребро создаёт цикл
        if (size[ra] < size[rb]) { int t = ra; ra = rb; rb = t; }
        parent[rb] = ra;
        size[ra] += size[rb];
        return true;
    }
}
```

Проверено: после `union(0,1)` и `union(1,2)` вызов `union(0,2)` возвращает `false` — это ребро замыкает цикл. Обе оптимизации вместе дают амортизированную сложность почти `O(1)` (обратная функция Аккермана).

</details>

## 12. Куча и top-K

`[ ]` **Короткий ответ:** `PriorityQueue` в Java — min-heap: голова — наименьший элемент. `offer`/`poll` — `O(log n)`, `peek` — `O(1)`, `contains` и `remove(Object)` — `O(n)` ([PriorityQueue, исходники OpenJDK](https://github.com/openjdk/jdk/blob/master/src/java.base/share/classes/java/util/PriorityQueue.java)). Для k наибольших держите min-heap размера `k`: `O(n log k)` времени и `O(k)` памяти.

Max-heap: `new PriorityQueue<>(Comparator.reverseOrder())`. `null` в очередь класть нельзя.

### Задача 23. k наибольших элементов

`[ ]` Ожидаемый результат: `[3,2,1,5,6,4], k=2 → [6, 5]`.

<details>
<summary>Решение</summary>

```java
static List<Integer> topK(int[] nums, int k) {
    PriorityQueue<Integer> heap = new PriorityQueue<>();  // min-heap
    for (int x : nums) {
        heap.add(x);
        if (heap.size() > k) heap.poll();                 // выкинуть наименьший
    }
    List<Integer> r = new ArrayList<>(heap);
    r.sort(Comparator.reverseOrder());
    return r;
}
```

</details>

**Уточнение интервьюера:** «Почему не отсортировать?» — сортировка `O(n log n)` и требует всех данных в памяти. Куча размера `k` работает с потоком и при `k ≪ n` быстрее. Если нужен полный порядок — проще сортировка. Для одного k-го элемента есть quickselect со средним `O(n)`.

### Задача 24. k самых частых

`[ ]` Ожидаемый результат: `[1,1,1,2,2,3], k=2 → [1, 2]`.

<details>
<summary>Решение</summary>

```java
static List<Integer> topKFrequent(int[] nums, int k) {
    Map<Integer, Integer> count = new HashMap<>();
    for (int x : nums) count.merge(x, 1, Integer::sum);
    PriorityQueue<Map.Entry<Integer, Integer>> heap =
        new PriorityQueue<>(Map.Entry.comparingByValue());
    for (var e : count.entrySet()) {
        heap.add(e);
        if (heap.size() > k) heap.poll();
    }
    List<Integer> r = new ArrayList<>();
    while (!heap.isEmpty()) r.add(heap.poll().getKey());
    Collections.reverse(r);
    return r;
}
```

Альтернатива за `O(n)` — bucket sort: массив списков, где индекс — частота.

</details>

<details>
<summary>Медиана потока</summary>

Две кучи: max-heap для нижней половины и min-heap для верхней. Размеры отличаются не больше чем на 1. Медиана — вершина большей кучи или среднее двух вершин. Добавление `O(log n)`, медиана `O(1)`.

</details>

## 13. Backtracking

`[ ]` **Короткий ответ:** перебор с возвратом — рекурсивно строим решение по шагам, после рекурсивного вызова откатываем последний выбор. Нужно явно назвать: состояние, варианты выбора, условие завершения, откат и отсечения.

```java
void search(State state) {
    if (isComplete(state)) { saveAnswer(state); return; }
    for (Choice choice : choices(state)) {
        if (!isAllowed(choice, state)) continue;   // отсечение
        apply(choice, state);
        search(state);
        undo(choice, state);                       // откат
    }
}
```

### Задача 25. Все подмножества

`[ ]` Ожидаемый результат: `[1,2] → [[], [1], [1,2], [2]]`; для `[1,2,3]` — 8 подмножеств.

<details>
<summary>Решение</summary>

```java
static List<List<Integer>> subsets(int[] nums) {
    List<List<Integer>> result = new ArrayList<>();
    backtrack(nums, 0, new ArrayList<>(), result);
    return result;
}

static void backtrack(int[] nums, int start, List<Integer> current, List<List<Integer>> result) {
    result.add(new ArrayList<>(current));        // копия!
    for (int i = start; i < nums.length; i++) {
        current.add(nums[i]);
        backtrack(nums, i + 1, current, result);
        current.remove(current.size() - 1);       // откат
    }
}
```

Время `O(n · 2ⁿ)`: `2ⁿ` подмножеств, каждое копируется за `O(n)`.

</details>

**Типичная ошибка:** `result.add(current)` без копии. В результат попадёт одна и та же ссылка, и в конце все элементы окажутся пустыми списками.

<details>
<summary>Перестановки</summary>

Для комбинаций передают стартовый индекс, чтобы не повторять наборы. Для перестановок отмечают использованные элементы. Для `[1,2,3]` — 6 перестановок.

```java
static void permute(int[] nums, boolean[] used, List<Integer> cur, List<List<Integer>> res) {
    if (cur.size() == nums.length) { res.add(new ArrayList<>(cur)); return; }
    for (int i = 0; i < nums.length; i++) {
        if (used[i]) continue;
        used[i] = true; cur.add(nums[i]);
        permute(nums, used, cur, res);
        cur.remove(cur.size() - 1); used[i] = false;
    }
}
```

</details>

## 14. Динамическое программирование

`[ ]` **Короткий ответ:** DP применяют, когда задача распадается на перекрывающиеся подзадачи, а оптимальный ответ собирается из оптимальных ответов меньших подзадач. Перед кодом назовите пять вещей: состояние, переход, база, порядок вычисления, где лежит ответ.

| Шаг | Вопрос | Пример (лесенка) |
|---|---|---|
| Состояние | Что значит `dp[i]`? | число способов дойти до ступеньки `i` |
| Переход | Из каких меньших состояний? | `dp[i] = dp[i-1] + dp[i-2]` |
| База | Ответ для самых маленьких входов | `dp[0] = dp[1] = 1` |
| Порядок | Что нужно вычислить раньше? | по возрастанию `i` |
| Ответ | Где он? | `dp[n]` |

Рекурсия с кешем (мемоизация, сверху вниз) и таблица (табуляция, снизу вверх) — две формы одного DP. Если для перехода нужны только последние значения, таблицу сжимают до нескольких переменных.

**DP или жадный алгоритм?** Жадный берёт локально лучший шаг и требует доказательства (обменный аргумент, инвариант). Контрпример быстро его опровергает: для монет `[1, 3, 4]` и суммы 6 жадный выбор даёт `4+1+1` (3 монеты), а оптимум `3+3` (2 монеты).

### Задача 26. Грабитель

`[ ]` Нельзя брать два соседних дома. Максимальная сумма? Ожидаемый результат: `[2,7,9,3,1] → 12`.

<details>
<summary>Решение</summary>

```java
static int rob(int[] nums) {
    int prev2 = 0, prev1 = 0;            // dp[i-2], dp[i-1]
    for (int x : nums) {
        int cur = Math.max(prev1, prev2 + x);  // пропустить дом или взять его
        prev2 = prev1;
        prev1 = cur;
    }
    return prev1;
}
```

Время `O(n)`, память `O(1)`.

</details>

### Задача 27. Размен монет

`[ ]` Минимальное число монет для суммы. Ожидаемый результат: `[1,2,5], 11 → 3`; `[2], 3 → -1`.

<details>
<summary>Решение</summary>

```java
static int coinChange(int[] coins, int amount) {
    int[] dp = new int[amount + 1];              // dp[a] — минимум монет для суммы a
    Arrays.fill(dp, Integer.MAX_VALUE);
    dp[0] = 0;
    for (int a = 1; a <= amount; a++)
        for (int c : coins)
            if (c <= a && dp[a - c] != Integer.MAX_VALUE)   // защита от переполнения
                dp[a] = Math.min(dp[a], dp[a - c] + 1);
    return dp[amount] == Integer.MAX_VALUE ? -1 : dp[amount];
}
```

Время `O(amount · coins)`.

</details>

### Задача 28. Рюкзак 0/1

`[ ]` Веса `[1,3,4]`, ценности `[15,20,30]`, вместимость 4. Каждый предмет можно взять один раз. Ожидаемый результат: `35` (предметы весом 1 и 3).

<details>
<summary>Решение</summary>

```java
static int knapsack01(int[] w, int[] v, int cap) {
    int[] dp = new int[cap + 1];                  // dp[c] — лучшая ценность при вместимости c
    for (int i = 0; i < w.length; i++)
        for (int c = cap; c >= w[i]; c--)         // справа налево!
            dp[c] = Math.max(dp[c], dp[c - w[i]] + v[i]);
    return dp[cap];
}
```

</details>

**Уточнение интервьюера:** «Что будет, если обходить вместимость слева направо?»

<details>
<summary>Ответ</summary>

Проверено запуском: получится `60` вместо `35`. При обходе слева направо `dp[c - w[i]]` уже обновлён с учётом текущего предмета, и предмет весом 1 и ценностью 15 «берётся» четыре раза. Это решение другой задачи — неограниченного рюкзака. Справа налево `dp[c - w[i]]` ещё хранит значение без текущего предмета.

</details>

<details>
<summary>Ещё задачи: LCS, редакционное расстояние, LIS</summary>

**LCS** (наибольшая общая подпоследовательность): `"abcde", "ace" → 3`. `dp[i][j]` — ответ для префиксов длины `i` и `j`.

```java
dp[i][j] = a.charAt(i-1) == b.charAt(j-1)
    ? dp[i-1][j-1] + 1
    : Math.max(dp[i-1][j], dp[i][j-1]);
```

**Редакционное расстояние** (Левенштейн): `"horse", "ros" → 3`. База `dp[i][0] = i`, `dp[0][j] = j`.

```java
dp[i][j] = a.charAt(i-1) == b.charAt(j-1)
    ? dp[i-1][j-1]
    : 1 + Math.min(dp[i-1][j-1], Math.min(dp[i-1][j], dp[i][j-1])); // замена, удаление, вставка
```

**LIS** (наибольшая возрастающая подпоследовательность) за `O(n log n)`: `[10,9,2,5,3,7,101,18] → 4`. `tails[k]` — наименьший возможный хвост возрастающей подпоследовательности длины `k + 1`.

```java
static int lis(int[] nums) {
    List<Integer> tails = new ArrayList<>();
    for (int x : nums) {
        int i = Collections.binarySearch(tails, x);
        if (i < 0) i = -(i + 1);                 // точка вставки
        if (i == tails.size()) tails.add(x); else tails.set(i, x);
    }
    return tails.size();
}
```

</details>

## 15. Битовые операции и переполнение

`[ ]` **Короткий ответ:** `x & 1` — чётность; `x & (x - 1)` сбрасывает младший единичный бит; `a ^ a = 0` помогает найти непарный элемент. В Java `int` — 32 бита со знаком, сдвиг берётся по модулю 32, поэтому для больших сдвигов нужен `1L`.

Все значения проверены запуском:

| Выражение | Результат | Почему |
|---|---|---|
| `1 << 31` | `-2147483648` | бит знака |
| `1 << 32` | `1` | для `int` сдвиг берётся по модулю 32 |
| `1L << 32` | `4294967296` | `long`, 64 бита |
| `100_000 * 100_000` | `1410065408` | переполнение `int` |
| `(long) 100_000 * 100_000` | `10000000000` | приведение **до** умножения |
| `x > 0 && (x & (x - 1)) == 0` при `x = Integer.MIN_VALUE` | `false` | без `x > 0` было бы `true` |

<details>
<summary>Задачи: степень двойки, непарный элемент, число единиц</summary>

```java
static boolean isPowerOfTwo(int x) { return x > 0 && (x & (x - 1)) == 0; }   // 64 → true, 0 → false

static int singleNumber(int[] nums) {          // [4,1,2,1,2] → 4
    int r = 0;
    for (int x : nums) r ^= x;                 // пары взаимно уничтожаются
    return r;
}

static int bitCount(int x) {                    // 0b1011 → 3; в JDK есть Integer.bitCount
    int c = 0;
    while (x != 0) { x &= x - 1; c++; }
    return c;
}
```

Маска подмножества: для `n ≤ 20` все подмножества можно перебрать как числа от `0` до `(1 << n) - 1`.

</details>

**Типичная ошибка:** `(long) (a * b)`. Приведение после умножения не помогает — переполнение уже произошло. Нужно `(long) a * b`.

### Задача 29. Поворот матрицы

`[ ]` Поверните квадратную матрицу на 90° по часовой стрелке на месте.

Ожидаемый результат: `[[1,2,3],[4,5,6],[7,8,9]] → [[7,4,1],[8,5,2],[9,6,3]]`.

<details>
<summary>Решение</summary>

```java
static void rotate(int[][] m) {
    int n = m.length;
    for (int i = 0; i < n; i++)                 // 1. транспонировать
        for (int j = i + 1; j < n; j++) {
            int t = m[i][j]; m[i][j] = m[j][i]; m[j][i] = t;
        }
    for (int[] row : m)                          // 2. развернуть каждую строку
        for (int l = 0, r = n - 1; l < r; l++, r--) {
            int t = row[l]; row[l] = row[r]; row[r] = t;
        }
}
```

Против часовой: транспонировать и развернуть столбцы. Во внутреннем цикле `j` начинается с `i + 1`: иначе каждая пара поменяется дважды и матрица вернётся в исходное состояние.

</details>

- Скользящее окно по времени: счётчики по минутным корзинам, старые корзины вычитаются.
- top-10 — min-heap размера 10 по счётчику, пересчёт по запросу или периодически.
- Если уникальных запросов слишком много для памяти — приближённые структуры: Count-Min Sketch для частот и куча кандидатов (в Redis 8 есть встроенный Top-K, см. RedisAndCaching.md).
- Назвать компромисс: точность против памяти.

</details>

<details>
<summary>4. «Есть словарь и слово. Найдите минимальное число замен одной буквы, чтобы получить целевое слово, проходя только через слова из словаря».</summary>

Граф неявный: вершины — слова, ребро — отличие в одной букве. Кратчайший путь без весов → BFS. Соседей генерируют заменой каждой буквы на `a..z` и проверкой в `HashSet` — это `O(L · 26)` на слово вместо сравнения со всем словарём. Улучшение — двусторонний BFS от начала и от конца.

</details>

## 18. Чек-лист перед тем как сказать «готово»

- [ ] Пустой вход, один элемент, все элементы одинаковы, ответа нет.
- [ ] Границы циклов: `left < right` и `left <= right` — разные инварианты.
- [ ] Переполнение: `long` и приведение **до** операции.
- [ ] Дубликаты: нужно любое вхождение, первое, последнее или только уникальные ответы?
- [ ] Сортировка меняет входной массив — это допустимо?
- [ ] Граф может быть несвязным — обход из каждой непосещённой вершины.
- [ ] В результат backtracking добавлена копия, а не ссылка.
- [ ] Проговорён инвариант цикла.
- [ ] Названы время и память, включая стек рекурсии.

## Приложение: как проверять свои решения

Все задачи файла проверены одним стендом. Свои решения удобно проверять так же: один файл, запуск без сборки через `java Algo.java` (Java 11+).

```java
import java.util.*;

public class Algo {
    static int fails = 0;

    static void check(String name, Object got, Object expected) {
        boolean ok = Objects.deepEquals(got, expected);   // deepEquals сравнивает и массивы
        if (!ok) fails++;
        String shown = got instanceof int[] a ? Arrays.toString(a) : String.valueOf(got);
        System.out.printf("%-30s %s got=%s%n", name, ok ? "OK" : "FAIL", shown);
    }

    public static void main(String[] args) {
        check("twoSum", twoSum(new int[] {2, 7, 11, 15}, 9), new int[] {0, 1});
        check("kadane all negative", maxSubArray(new int[] {-3, -1, -2}), -1);
        check("abba", lengthOfLongestSubstring("abba"), 2);
        // ...
        System.out.println(fails == 0 ? "ALL OK" : "FAILS: " + fails);
    }

    // сюда — решения
}
```

Для каждой задачи добавляйте минимум три проверки: пример из условия, граничный случай (пустой вход, один элемент) и ловушку (отрицательные числа, переполнение, дубликаты).
