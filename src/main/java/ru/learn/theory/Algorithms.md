# Алгоритмы — шпаргалка для задач

Цель этой страницы — быстро распознать подход и понять, с чего начать. На собеседовании сначала уточните входные данные и ограничения, проговорите простой вариант, затем улучшите его и объясните сложность.

## Быстрый выбор подхода

| Признак в условии | Что попробовать |
|---|---|
| Массив отсортирован; нужно найти пару, границу или позицию | **Два указателя** или **бинарный поиск** |
| Ищем непрерывный подмассив/подстроку | **Скользящее окно** или **префиксные суммы** |
| Нужно быстро проверять наличие, частоты, дубликаты | **HashSet / HashMap** |
| Нужно найти следующий больший/меньший элемент | **Монотонный стек** |
| Нужны k наибольших/наименьших элементов | **Куча / PriorityQueue** |
| Дерево/граф, кратчайший путь без весов | **BFS** |
| Обойти все варианты, комбинации или перестановки | **Backtracking** |
| Максимум/минимум при локально лучшем выборе | Проверьте **жадный алгоритм**; докажите, почему выбор безопасен |
| Ответ строится из ответов на меньшие подзадачи | **Динамическое программирование** |
| Проверить связность или объединять группы | **Union-Find (DSU)** |

## 1. Сначала оцените ограничения и сложность

Сложность описывает, как растет время или память с размером входа `n`.

| Сложность | Пример | Обычно подходит для |
|---|---|---|
| `O(1)` | доступ к элементу массива по индексу | любого размера |
| `O(log n)` | бинарный поиск | очень больших входов |
| `O(n)` | один проход по массиву | больших входов |
| `O(n log n)` | эффективная сортировка | больших входов |
| `O(n²)` | сравнение каждой пары | небольших входов |
| `O(2ⁿ)`, `O(n!)` | перебор подмножеств/перестановок | только маленьких `n` или с сильным отсечением |

- Два вложенных прохода не всегда означают `O(n²)`: если указатели только двигаются вперед и суммарно проходят массив по одному разу, это `O(n)`.
- Учитывайте дополнительную память: сортировка может менять исходный массив, хеш-таблица обычно требует `O(n)`.
- Если ограничения позволяют лишь несколько миллионов простых операций, квадратичное решение часто слишком медленное.

## 2. Массивы, строки и хеш-таблицы

### Частоты, наличие и дубликаты

Если многократно ищете элемент или считаете частоты, вместо повторного перебора используйте `HashSet` или `HashMap`.

```java
Map<Integer, Integer> count = new HashMap<>();
for (int x : nums) {
    count.merge(x, 1, Integer::sum);
}
```

- Пара «значение → частота» помогает находить повторы, анаграммы и элементы с заданной частотой.
- Пара «значение → индекс» полезна в задачах вроде Two Sum.
- Для фиксированного небольшого алфавита массив частот обычно проще и быстрее `HashMap` (например, `int[26]`).
- Хеш-таблица дает ожидаемое `O(1)` на поиск/вставку, но использует дополнительную память.

### Максимальная сумма подмассива (алгоритм Кадане)

Если подмассив должен быть **непустым**, поддерживайте лучший отрезок, заканчивающийся в текущей позиции:

```text
current = max(nums[i], current + nums[i])
best = max(best, current)
```

Инициализируйте обе переменные первым элементом, а не нулем: иначе массив из отрицательных чисел даст неверный ответ. Время `O(n)`, память `O(1)`.

### Two Sum: дополнение до цели

Для каждого числа `x` ищите, встречалось ли уже `target - x`.

```java
Map<Integer, Integer> indexByValue = new HashMap<>();
for (int i = 0; i < nums.length; i++) {
    int need = target - nums[i];
    if (indexByValue.containsKey(need)) {
        return new int[] { indexByValue.get(need), i };
    }
    indexByValue.put(nums[i], i);
}
```

Время `O(n)`, память `O(n)`. Сначала проверяем дополнение, потом добавляем текущее число, чтобы не использовать один элемент дважды.

## 3. Два указателя

Удобны, если массив отсортирован, нужно изменить массив на месте или сравнивать элементы с обоих концов.

### Указатели навстречу

```java
int left = 0, right = nums.length - 1;
while (left < right) {
    int sum = nums[left] + nums[right];
    if (sum == target) {
        // нашли ответ
        break;
    } else if (sum < target) {
        left++;       // нужно увеличить сумму
    } else {
        right--;      // нужно уменьшить сумму
    }
}
```

- Работает для пары с заданной суммой в **отсортированном** массиве: `O(n)` вместо перебора пар `O(n²)`.
- Один указатель можно двигать от начала, другой — от конца: палиндром, контейнер с водой.
- Обоснуйте движение: почему отброшенные варианты уже не могут быть ответом?

### Медленный и быстрый указатели

Оба движутся в одном направлении, но с разной скоростью или назначением.

- **Удаление/сжатие на месте**: `read` перебирает элементы, `write` указывает позицию следующего сохраняемого. Применяется для удаления элементов, нулей, дублей в отсортированном массиве. Возвращаемая длина — обычно `write`.
- **Поиск цикла**: `slow` идет на 1 шаг, `fast` на 2. Если цикл есть, указатели встретятся. Если `fast == null` или `fast.next == null`, список конечен.
- **Середина списка**: после завершения обхода `slow` находится примерно в середине.

Важно: при работе со списком проверяйте `fast != null` и `fast.next != null` до чтения `fast.next.next`.

### Слияние двух отсортированных последовательностей

Сравнивайте текущие элементы двух последовательностей и переносите меньший. Если результат записывается в свободный буфер **в конце первого массива**, заполняйте его справа налево, чтобы не затереть еще не прочитанные значения.

## 4. Скользящее окно

Используйте для **непрерывного** участка массива или строки: максимальная/минимальная длина, подстрока, сумма/частота в окне.

```java
int left = 0;
for (int right = 0; right < nums.length; right++) {
    // добавить nums[right] в состояние окна

    while (/* окно нарушает условие */) {
        // убрать nums[left] из состояния окна
        left++;
    }

    // обновить ответ по допустимому окну [left, right]
}
```

- Каждый указатель проходит массив не более одного раза: обычно `O(n)`.
- Для «самой длинной подстроки без повторов» храните частоты или последний индекс символа.
- Для «минимального окна, содержащего все нужные символы» расширяйте окно вправо до выполнения условия, затем сжимайте слева, пока условие сохраняется.
- Частый вариант — окно фиксированной длины `k`: добавили правый элемент, удалили элемент, выпавший слева, обновили ответ.

**Важная ловушка:** обычное окно хорошо работает, когда при расширении/сжатии условие меняется предсказуемо. Для подмассива с суммой `>= target` и отрицательными числами такой подход обычно не работает — используйте префиксные суммы и другой метод. Для массива только с неотрицательными числами такое окно подходит.

## 5. Префиксные суммы

Префиксная сумма позволяет быстро получить сумму отрезка:

```text
prefix[0] = 0
prefix[i + 1] = prefix[i] + nums[i]
sum(left..right) = prefix[right + 1] - prefix[left]
```

После построения за `O(n)` сумма любого отрезка считается за `O(1)`.

### Подмассив с суммой `k`

Если нужно посчитать количество подмассивов с суммой `k`, используйте частоты префиксных сумм:

```java
Map<Long, Integer> seen = new HashMap<>();
seen.put(0L, 1);
long prefix = 0;
long answer = 0;

for (int x : nums) {
    prefix += x;
    answer += seen.getOrDefault(prefix - k, 0);
    seen.merge(prefix, 1, Integer::sum);
}
```

Работает и с отрицательными числами; время `O(n)`, память `O(n)`. Используйте `long`, если сумма может выйти за пределы `int`.

## 6. Бинарный поиск

Применим не только для поиска элемента: ищите ответ на **монотонном** условии — если значение `x` подходит, то подходят и все значения больше (или наоборот).

### Поиск элемента в отсортированном массиве

```java
int left = 0, right = nums.length - 1;
while (left <= right) {
    int mid = left + (right - left) / 2;
    if (nums[mid] == target) return mid;
    if (nums[mid] < target) left = mid + 1;
    else right = mid - 1;
}
return -1;
```

- Время `O(log n)`.
- Формула середины `left + (right - left) / 2` снижает риск переполнения.
- Для обычного поиска допустимо вернуть любое вхождение; если нужны первое/последнее или точка вставки, ищите **границу**.

### Нижняя граница (lower bound)

Найти первый индекс, где `nums[index] >= target`:

```java
int left = 0, right = nums.length; // полуинтервал [left, right)
while (left < right) {
    int mid = left + (right - left) / 2;
    if (nums[mid] < target) left = mid + 1;
    else right = mid;
}
// left — индекс первого элемента >= target; может быть nums.length
```

Верхняя граница — первый индекс, где элемент `> target`; число вхождений `target` равно `upperBound - lowerBound`.

### Бинарный поиск по ответу

Спросите себя: **можно ли проверить, подходит ли предложенный ответ `x`, и монотонна ли эта проверка?** Примеры — минимальная скорость, достаточная для работы; минимальная вместимость; максимум минимального расстояния.

- Найдите диапазон возможного ответа.
- Напишите `can(x)` — проверку допустимости.
- Определите, в какую сторону сдвигается граница при `true` и `false`.
- Проверьте граничные значения и случай, когда подходящего ответа нет.

## 7. Сортировка и интервалы

Сортируйте, если это упрощает порядок обработки, позволяет применять два указателя или объединять интервалы. Обычно стоимость — `O(n log n)`.

### Слияние интервалов

1. Отсортируйте интервалы по началу.
2. Если следующий начинается не позже конца текущего — объедините (`end = max(end, nextEnd)`).
3. Иначе сохраните текущий и начните новый.

Уточните в условии, считаются ли касающиеся интервалы пересекающимися: сравнение может быть `<=` или `<`.

### Встречи и занятость ресурсов

Для поиска максимального числа одновременных событий удобно отдельно отсортировать времена начала и конца, либо использовать min-heap концов текущих интервалов.

## 8. Стек, очередь и монотонная структура

### Стек

Подходит для скобок, отмены последнего действия, обработки вложенности и задач «следующий элемент».

- Сбалансированные скобки: открывающую скобку кладем в стек; закрывающая должна соответствовать верхней.
- **Монотонный стек** поддерживает элементы в возрастающем или убывающем порядке. Удаляйте с вершины элементы, для которых найден ответ.
- Примеры: следующий больший элемент справа, температура до более теплого дня, максимальный прямоугольник в гистограмме.
- Для кругового массива иногда проход делают дважды (`2 * n`), индексируя через `% n`.

### Очередь и BFS

Очередь `ArrayDeque` подходит для обхода уровнями и задач «первым пришел — первым обработан».

- **BFS** находит кратчайшее расстояние в невзвешенном графе (или графе с одинаковой стоимостью ребер).
- Помечайте вершину посещенной **при добавлении в очередь**, иначе ее могут добавить несколько раз.
- Для матрицы используйте четыре/восемь направлений и проверку границ.

Минимальный каркас обходов (для вершин `0..n-1`):

```java
void dfs(int node, List<List<Integer>> graph, boolean[] visited) {
    visited[node] = true;
    for (int next : graph.get(node)) {
        if (!visited[next]) dfs(next, graph, visited);
    }
}

void bfs(int start, List<List<Integer>> graph, boolean[] visited) {
    Queue<Integer> queue = new ArrayDeque<>();
    visited[start] = true;
    queue.add(start);
    while (!queue.isEmpty()) {
        int node = queue.remove();
        for (int next : graph.get(node)) {
            if (!visited[next]) {
                visited[next] = true;
                queue.add(next);
            }
        }
    }
}
```

Чтобы обойти весь несвязный граф, вызовите обход из каждой вершины, которая еще не посещена.

### Монотонная очередь

Для максимума/минимума в каждом окне длины `k` храните индексы кандидатов в `ArrayDeque`:

1. удалите из начала индексы, вышедшие за границу окна;
2. удалите с конца элементы, хуже нового кандидата;
3. добавьте новый индекс; в начале очереди — максимум (или минимум).

Время `O(n)`: каждый индекс добавляется и удаляется не более одного раза.

## 9. Связные списки

- **Разворот списка**: держите `prev`, `current`, `next`; перенаправьте `current.next` на `prev`, затем сдвиньте указатели. Время `O(n)`, память `O(1)`.
- **Цикл**: медленный/быстрый указатели; для нахождения начала цикла после встречи один указатель поставьте в начало, затем двигайте оба по одному шагу — место встречи будет входом в цикл.
- **Слияние отсортированных списков**: фиктивный `dummy`-узел упрощает создание результата; каждый раз добавляйте меньший узел.
- **Удаление узла по условию**: фиктивный узел также упрощает удаление головы.
- Перед изменением ссылок сохраните следующий узел, иначе можно потерять остаток списка.

## 10. Деревья и обходы

### DFS: в глубину

Используйте рекурсию или явный стек. Хорошо подходит для проверки свойств, поиска пути и вычисления значения из поддеревьев.

Порядок обхода:
- preorder: узел → левое → правое;
- inorder: левое → узел → правое (в BST дает значения по возрастанию);
- postorder: левое → правое → узел (удобно, если ответ зависит от детей).

### BFS: по уровням

Используйте очередь, если важны уровни, минимальное число ребер или ближайший узел. В начале каждого уровня запомните текущий `queue.size()`, чтобы обработать ровно этот уровень.

### Частые задачи на деревья

- Максимальная глубина: `1 + max(depth(left), depth(right))`.
- Сбалансированность: постorder; вычисляйте высоту и сразу возвращайте признак ошибки, не пересчитывайте высоту поддерева многократно.
- Путь/сумма пути: передавайте накопленное состояние вниз или объединяйте результаты детей.
- BST: для проверки передавайте допустимый диапазон `(min, max)`, а не сравнивайте только с непосредственным родителем.
- Общий предок: определите, где искомые узлы расходятся; для BST можно использовать порядок значений.

Рекурсия на вырожденном дереве может иметь глубину `O(n)` и переполнить стек; при больших входах рассмотрите итеративный обход.

## 11. Графы

Граф удобно хранить списком смежности: для каждой вершины — список соседей. Это обычно занимает `O(V + E)`, где `V` — вершины, `E` — ребра.

### DFS / BFS

- Используйте DFS/BFS для достижимости, числа компонент, островов в матрице, проверки связности.
- Список посещенных вершин обязателен в графе с циклами.
- Для неориентированного графа добавляйте ребро в списки обоих концов.
- Для кратчайшего пути в невзвешенном графе — BFS; расстояние можно хранить в массиве или парами `(вершина, расстояние)`.

### Топологическая сортировка

Для ориентированного ациклического графа (DAG): посчитайте входящие степени, добавьте вершины степени `0` в очередь, удаляйте их и уменьшайте степени соседей. Если обработано меньше `V` вершин — в графе есть цикл.

Применение: зависимости задач, расписание курсов, порядок сборки.

### Кратчайший путь с весами

- **Dijkstra** — неотрицательные веса; min-heap по текущему расстоянию. Устаревшие записи в куче пропускайте, если их расстояние больше уже известного.
- **Bellman–Ford** — допускает отрицательные веса и выявляет отрицательный цикл; медленнее, `O(VE)`.
- **Floyd–Warshall** — кратчайшие пути между всеми парами, `O(V³)` времени и `O(V²)` памяти.
- Не применяйте Dijkstra с отрицательными ребрами.

### Union-Find (DSU)

Эффективно объединяет группы и проверяет, принадлежат ли элементы одной компоненте.

- `find(x)` находит представителя группы.
- `union(a, b)` объединяет группы.
- Используйте сжатие путей и объединение по размеру/рангу: амортизированная сложность почти `O(1)`.
- Применение: компоненты связности, обнаружение цикла в неориентированном графе, алгоритм Краскала для минимального остовного дерева.

## 12. Куча и top-K

В Java `PriorityQueue` по умолчанию — min-heap: `peek()` возвращает минимум.

- Нужны `k` наименьших — min-heap по всем элементам или max-heap размера `k`.
- Нужны `k` наибольших — min-heap размера `k`: если новый элемент больше вершины, замените вершину.
- Сложность хранения `k` элементов: `O(k)` памяти, обработка `n` элементов — `O(n log k)`.
- Для медианы потока используют две кучи: max-heap нижней половины и min-heap верхней.

Куча полезна, когда нужен следующий экстремальный элемент много раз; если требуется просто отсортировать все данные, обычно проще сортировка.

## 13. Backtracking — перебор с возвратом

Используйте, если нужно перечислить все допустимые комбинации, подмножества, расстановки или найти путь с ограничениями.

```java
void search(State state) {
    if (isComplete(state)) {
        saveAnswer(state);
        return;
    }

    for (Choice choice : choices(state)) {
        if (!isAllowed(choice, state)) continue; // отсечение
        apply(choice, state);
        search(state);
        undo(choice, state);                     // откат
    }
}
```

- Всегда понимайте, что является состоянием, выбором, условием завершения и правилом отката.
- Добавляйте отсечение: не продолжайте ветку, если она уже не может дать допустимый или лучший ответ.
- Число вариантов может расти экспоненциально: оценивайте размер входа заранее.
- Для комбинаций задайте стартовый индекс, чтобы не генерировать перестановки одного набора; для перестановок отмечайте уже использованные элементы.

## 14. Динамическое программирование (DP)

Признаки DP: задачу можно разбить на перекрывающиеся подзадачи, а оптимальный ответ строится из ответов на меньшие подзадачи.

Перед кодом явно определите:

1. **Состояние**: что означает `dp[i]` или `dp[i][j]`?
2. **Переход**: из каких меньших состояний получается текущее?
3. **База**: ответы для самых маленьких/пустых входов.
4. **Порядок вычисления**: какие состояния нужны раньше?
5. **Итог**: где находится ответ — `dp[n]`, `max(dp)` или другая ячейка?

Если решение естественно выражается рекурсией, но одни и те же аргументы встречаются снова, добавьте **мемоизацию** (кэш по параметрам). Если нужна таблица меньших состояний — используйте **табуляцию**. Это две формы одного DP.

### Примеры моделей

- Число способов дойти до ступеньки: `dp[i] = dp[i - 1] + dp[i - 2]`.
- Максимальная сумма без соседних элементов: `dp[i] = max(dp[i - 1], dp[i - 2] + nums[i])`.
- Рюкзак: `dp[i][capacity]` — лучший ответ на первых `i` предметах при такой вместимости. Для каждого предмета выбор: взять или пропустить.
- LCS/редакционное расстояние: `dp[i][j]` описывает ответы для префиксов длины `i` и `j`.
- Сетка: переход обычно идет сверху и слева; препятствие исключает состояние.

Сначала напишите понятное решение с таблицей, потом при необходимости сократите память. Для 0/1-рюкзака при одномерном массиве вместимость обходят **справа налево**, иначе предмет можно использовать несколько раз.

Отличайте DP от жадного подхода: локально лучший выбор не всегда приводит к глобальному оптимуму. Для жадного алгоритма нужно обоснование (обменный аргумент, инвариант или доказанная структура задачи).

## 15. Битовые операции

- `x & 1` — проверить младший бит (четность).
- `x & (x - 1)` — сбросить младший установленный бит; проверка степени двойки: `x > 0 && (x & (x - 1)) == 0`.
- `a ^ a == 0`, `a ^ 0 == a`: XOR помогает найти одиночный элемент, если остальные встречаются парами.
- Используйте `1 << bit` для маски небольшого множества признаков.

Следите за знаковостью и шириной типа: в Java `int` — 32 бита, `long` — 64. Для сдвига на большие позиции используйте `1L << bit`.

## 16. Матрицы и направления

Для обхода сетки заведите массивы смещений:

```java
int[] dr = {-1, 1, 0, 0};
int[] dc = {0, 0, -1, 1};
```

Для каждого соседа проверяйте границы, препятствия и признак посещения. Так решаются острова, распространение по клеткам и кратчайший путь BFS.

- Поворот/отражение матрицы: проверьте, можно ли сначала транспонировать, затем перевернуть строки или столбцы.
- Для обхода по спирали поддерживайте четыре границы и после каждого прохода сдвигайте соответствующую границу.
- Уточните, квадратная ли матрица, возможны ли пустые строки и считаются ли диагонали соседями.

## Частые ошибки и финальная проверка

- Пустой массив/строка, один элемент, все элементы одинаковы, ответ отсутствует.
- Границы циклов: `left < right` и `left <= right` означают разные инварианты.
- Индексы и длина — не одно и то же; проверьте последний допустимый индекс.
- Переполнение суммы/произведения: используйте `long` и преобразуйте **до** операции, например `(long) a * b`.
- Дубликаты: нужно найти любое вхождение, первое/последнее или уникальные ответы?
- Сортировка меняет порядок и может изменить входной массив — допустимо ли это?
- Граф может быть несвязным: запускайте обход из каждой еще не посещенной вершины, если нужны все компоненты.
- Проговорите инвариант цикла: что верно до и после каждой итерации?
- Объясните временную и пространственную сложность, включая рекурсию и вспомогательные структуры.
