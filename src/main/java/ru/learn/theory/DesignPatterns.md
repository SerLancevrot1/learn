# SOLID и паттерны проектирования

**Назови проблему, которую решает паттерн, и укажи, какая часть кода меняется независимо от остальных.**

## SOLID

| Принцип | Смысл | Пример на интервью |
|---|---|---|
| SRP | У модуля одна причина изменяться | Расчёт цены и отправка уведомлений меняются по разным причинам |
| OCP | Добавляй варианты через стабильную точку расширения | Новый тариф реализует интерфейс стратегии |
| LSP | Подтип сохраняет контракт базового типа | Реализация коллекции сохраняет обещания интерфейса |
| ISP | Клиент зависит только от нужных операций | Раздели чтение каталога и управление каталогом |
| DIP | Политика приложения зависит от абстракции на её границе | Use case работает с интерфейсом репозитория, адаптер использует JDBC |

## Что выбрать

| Паттерн | Зачем | Пример в проекте |
|---|---|---|
| Strategy | Менять алгоритм через композицию | [Стратегии полёта и голоса](../patterns/strategy/Duck.java) |
| Observer | Уведомлять подписчиков об изменении | [Данные о погоде](../patterns/observer/WeatherData.java) |
| Decorator | Обернуть объект того же интерфейса и добавить поведение | [Добавки к кофе](../patterns/decorator/CondimentDecorator.java) |
| Adapter | Преобразовать существующий интерфейс к ожидаемому | [Адаптер индейки](../patterns/adapter/DuckAdapter.java) |
| Command | Представить действие объектом, чтобы хранить или передавать его | [Команды пульта](../patterns/command/DistantController.java) |
| Factory Method | Отдать выбор создаваемого объекта подклассу | [Магазины пиццы](../patterns/factory/method/store/PizzaStore.java) |
| Abstract Factory | Создавать семейство совместимых объектов | [Компоненты телефона](../patterns/factory/abstractt/PhoneFabric.java) |
| Singleton | Управлять единственным экземпляром в заданной области | [Учебная реализация](../patterns/singleton/Singleton.java) |

**Частый вопрос.** Adapter меняет интерфейс для клиента. Decorator сохраняет интерфейс и добавляет поведение. Proxy управляет доступом или вызовом через тот же интерфейс. [Spring proxy](Spring.md)

**Практика.** Добавь новый вариант полёта в примере Strategy. Проверь, какой код пришлось изменить для регистрации стратегии и какой остался прежним.

## 10. SOLID

`[ ]` **Короткий ответ:** пять принципов объектного дизайна, которые уменьшают связанность и стоимость изменений. Их применяют, когда это оправдано, а не механически: лишние абстракции тоже стоят денег.

| Принцип | Суть | Признак нарушения |
|---|---|---|
| **S** — Single Responsibility | У модуля одна причина для изменения | Класс `OrderService` и считает налоги, и шлёт письма, и формирует PDF |
| **O** — Open/Closed | Поведение расширяется без правки стабильного кода | Новый способ оплаты требует нового `case` в пяти `switch` |
| **L** — Liskov Substitution | Подтип выполняет контракт базового типа | `Square extends Rectangle`, и `setWidth` неожиданно меняет высоту |
| **I** — Interface Segregation | Клиент не зависит от ненужных методов | Реализация интерфейса бросает `UnsupportedOperationException` |
| **D** — Dependency Inversion | Политика и детали зависят от абстракций | Бизнес-логика создаёт `new PostgresOrderRepository()` |

<details>
<summary>Пример Dependency Inversion</summary>

```java
// Абстракция принадлежит бизнес-слою и описывает то, что нужно ему
interface OrderRepository {
    Optional<Order> findById(long id);
    void save(Order order);
}

// Бизнес-логика зависит только от абстракции
final class OrderService {
    private final OrderRepository orders;
    OrderService(OrderRepository orders) { this.orders = orders; }
}

// Деталь реализует абстракцию; направление зависимости в коде — к бизнес-слою
final class JdbcOrderRepository implements OrderRepository { /* ... */ }
```

Вызов идёт от `OrderService` к `JdbcOrderRepository`, а зависимость в исходном коде — наоборот. Это и есть «инверсия». Бонус — `OrderService` тестируется с фейковым репозиторием без БД.

</details>

<details>
<summary>Пример Liskov: почему квадрат не прямоугольник</summary>

Код, работающий с `Rectangle`, вправе ожидать: после `setWidth(5)` и `setHeight(4)` площадь равна 20. `Square` должен держать стороны равными, поэтому `setHeight(4)` меняет и ширину — площадь 16. Подстановка ломает ожидания клиента, хотя «квадрат является прямоугольником» в математике. Выход: неизменяемые фигуры или общий интерфейс `Shape` с методом `area()` без сеттеров.

</details>
